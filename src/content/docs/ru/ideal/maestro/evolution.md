Когда память цепочек — IdeaL, каждая эволюция, которую запускает Maestro,
подключена к озеру. Сам Maestro идеи не выбирает и оценки не сообщает. Это
делает сервис эволюции через публичный API IdeaL.

## Что отправляет Maestro

При создании эксперимента эволюции Maestro добавляет:

| Поле | Значение |
| --- | --- |
| `enable_memory` | `true` |
| `memory_backend` | `ideal` |
| `memory_namespace` | Настроенное пространство IdeaL. |
| `memory_task_key` | Стабильный ключ задачи (ниже). |

Эти поля ставятся последними, поэтому ничто другое в запросе не может
перенаправить пространство. При включённом **Read only** или с памятью
`Library search` они не отправляются, и эволюция идёт без памяти.

## Ключ задачи

IdeaL оценивает идеи по задачам. Maestro строит ключ из цепочки:

- `task:<16 hex>`: SHA-256 описания задачи цепочки (пробелы схлопнуты,
  регистр приведён). Победители эволюции сохраняют описание, поэтому их
  следующие прогоны попадают на тот же ключ.
- `chain:<16 hex>`: если у цепочки нет описания задачи, хеш id исходной
  цепочки.

Так одна задача копит опыт между прогонами. Тот же ключ Библиотека
использует для списка «эволюций этой цепочки».

**Ограничение.** Ключ хеширует точную формулировку. Переформулированное
описание — это новая задача. Она начинает без локального опыта и только
заимствует опыт других задач и общий. Прогоны, запущенные до появления
стабильного ключа, к своей цепочке не привязаны («прогоны были до того, как
задача получила постоянный ключ»).

## Что делает сервис эволюции

1. **Перед каждой мутацией**: `POST /v1/retrieve` с `mode=evolution`, id
   прогона, новым id кандидата на каждое решение о мутации и коротким
   описанием задачи. Идеи из подборки попадают в промпт мутации. Около 30%
   подборок намеренно пустые (контроль).
2. **Если запрос не удался**: мутация идёт без идей, и результат по ней не
   сообщается. Озеро никогда не блокирует прогон.
3. **Когда потомок оценён**: `POST /v1/outcome` с `kind=mutation`, приростом
   `delta` (`null` для невалидного потомка) и идеями, которые потомок
   действительно использовал. Прерванные попытки и попытки без потомка не
   сообщаются: про идеи они ничего не говорят.
4. **Доставка**: результаты сначала пишутся в надёжную локальную очередь и
   отправляются асинхронно. Сбои сети, отмена и возобновление не теряют и не
   удваивают их; API идемпотентен на точных повторах.
5. **В конце естественно завершённого прогона**: `POST /v1/outcome` с
   `kind=run`, лучшая цепочка из архива под понятным названием, её оценка и
   идеи в её родословной. Отменённые и незавершённые прогоны итог не
   отправляют.

Лучшая цепочка становится цепочкой задачи в пространстве. Когда генерация
в следующий раз работает над той же задачей, каталог может предложить её как
отправную точку.

## Как следить за прогоном

- В карточке эволюции в чате есть **Радар идей** (см. [Радар](/ru/ideal/maestro/radar/)).
- Подписанная страница прогона (`run_url`) — собственный живой вид сервера.
- Граф в Библиотеке показывает прогон с выданными и применёнными идеями после
  первой записанной подборки.

## Ограничения

- Сторона эволюции — отдельный сервис. Что именно он сообщает (ключ задачи в
  каждом retrieve, `parent_score`, `metric`, `change`), зависит от его версии.
  Без `parent_score` и границ сила ранжирует сырые приросты, а не долю
  оставшегося диапазона. Без `change` извлечению на сервере не из чего
  учиться.
- Текст идеи попадает в мутацию как есть. Содержимое озера — подсказка, а не
  инструкция. Но любой, кто может писать в пространство, влияет на мутации.
  Давайте доступ к пространству только тем, кому доверяете.
- Атрибуция пути наивная: каждая идея в родословной лучшей цепочки получает
  победу на пути.
