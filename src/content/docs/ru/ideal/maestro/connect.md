Maestro работает с IdeaL через подключение к памяти. IdeaL — не отдельный
сервис. Это часть того же API GigaEvo Memory, где хранятся ваши цепочки.

## Настройки

В настольном приложении откройте **Settings → Research and Memory**.

| Поле | Что указать |
| --- | --- |
| **Memory base URL** | API памяти. Локальный стек Compose: `http://localhost:8000/api` (через nginx) или `http://localhost:8002` (прямой порт). Для облачного хранилища укажите адрес с префиксом `/api`. |
| **Memory API key** | Ваш ключ IdeaL. Хранится в системной связке ключей, агенту не показывается. |
| **Read only** | Никогда не писать в эту память. Для общих или облачных хранилищ, которые вы только смотрите. |
| **Chain memory** | `Library search` (по умолчанию) или `IdeaL (ideas + evolution learning)`. |
| **IdeaL namespace** | Обязательно для IdeaL. Латиница, цифры, `.`, `_`, `:`, `-`; начинается с буквы или цифры; до 128 символов; регистр важен. |

Те же настройки для CLI и TUI задаются переменными окружения:

```bash
CARE_MEMORY__BASE_URL=http://localhost:8000/api
CARE_MEMORY__API_KEY=<ключ>
CARE_MEMORY__RETRIEVAL_BACKEND=ideal      # по умолчанию legacy
CARE_MEMORY__IDEAL_NAMESPACE=my-team
CARE_MEMORY__READ_ONLY=false
```

Если `RETRIEVAL_BACKEND=ideal`, а пространство не задано, Maestro отклоняет
конфигурацию. Пустое `CARE_MEMORY__IDEAL_NAMESPACE=` означает «не задано».

Ключ должен иметь право читать и писать это пространство (см.
[Пространства и ключи](/ru/ideal/concepts/namespaces-and-keys/)). Частые
ошибки:

| Сообщение Maestro | Причина |
| --- | --- |
| «Хранилище идей ответило 401» | Ключ не принят или не дошёл до сервера. Вставьте в поле только сам ключ. |
| «… 403 … у ключа нет доступа к этому пространству идей» | Ключу нельзя работать с этим пространством. |
| «… 404 … адрес должен заканчиваться на /api» | Адрес ведёт на веб-интерфейс, а не на API. |

## Что меняет память цепочек IdeaL

| Область | `Library search` | `IdeaL` |
| --- | --- | --- |
| Подсказки генерации | Поиск по Библиотеке: сохранённые цепочки и карточки. | Один запрос `mode=catalog` с задачей: до 4 подсказок, поровну между цепочками задачи и идеями. Чтение каталога не записывается. |
| Эволюция | Без памяти. | Каждый прогон получает `memory_backend=ideal`, пространство и стабильный ключ задачи. Эволюция получает подборки идей и сообщает результаты. См. [Эволюция](/ru/ideal/maestro/evolution/). |
| Сохранение цепочек, идей, инструментов | Пространство владельца ключа. | Настроенное пространство IdeaL. |
| Библиотека → Идеи | Недоступно. | Граф идей, форма идеи, архив, радары прогонов. См. [Идеи в Библиотеке](/ru/ideal/maestro/library/). |
| Факты из чата | Локальная память. | По-прежнему локальная память. В IdeaL факты из чата не попадают. |

Генерация отправляет в каталог только ограниченный текст задачи. Вложения,
история чата и долговременные факты не отправляются.

## Режим «только чтение»

Когда включён **Read only**:

- форма идеи, архив и возврат из архива недоступны;
- эволюция идёт **без** памяти IdeaL, потому что эволюция с IdeaL пишет
  квитанции выдачи и результаты;
- генерация по-прежнему читает подсказки из каталога;
- подсказку идеи с радара прогона режим **не** блокирует. Это известный
  пробел: подсказка пишется в прогон на сервере.

## Проверка подключения

- Раздел «Идеи» в Библиотеке открывает граф настроенного пространства. Если
  граф недоступен, в сообщении будет HTTP-статус.
- Спросите агента «покажи пространства идей». Он вызовет
  `maestro_ideal_namespaces` и покажет пространства, доступные ключу, и
  возможности сервера (граф, хронология, добавление идей, инструменты, засев).

Maestro один раз читает актуальную схему OpenAPI сервера и по ней узнаёт,
какие функции IdeaL есть. На старом сервере недостающие функции скрываются
или помечаются недоступными, а не падают.
