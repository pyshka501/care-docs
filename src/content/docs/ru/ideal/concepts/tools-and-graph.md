## Инструменты

**Инструмент** — детерминированная возможность, которую может вызвать
цепочка: арифметика, нормализация дат, точный поиск. Это отдельная
версионируемая сущность (`/v1/tools`). Не идея и не шаг цепочки.

| Поле | Смысл |
| --- | --- |
| `tool_key` | Канонический ключ, уникальный в пространстве. Опыт переносится между пространствами по этому ключу. |
| `name`, `description` | Что делает. |
| `input_schema`, `output_schema` | JSON-схемы. |
| `runtime`, `implementation_ref`, хеш реализации | Где лежит код и как он запускается. |
| `status` | Выдаётся, пока не `archived`. |

Оба режима retrieve возвращают не больше `RETRIEVE_TOOL_LIMIT` (по
умолчанию 1) подходящих инструментов. Для полноты выдачи инструменты не
добавляются: нерелевантный инструмент не возвращается вовсе.

Инструмент нужен, когда LLM-шаг раз за разом ошибается в чём-то точном. Если
реализации пока нет, запишите потребность как идею («добавить
детерминированный шаг, который …»). В Maestro настоящие инструменты
создаются в мастерской инструментов: она пишет код и проверяет его в
песочнице. Форма идеи инструменты не создаёт.

## Цепочки в озере

Для IdeaL важны два вида цепочек:

- **Цепочки задач**: лучшая цепочка каждого завершённого прогона. Её
  сохраняет итог прогона с тегом `task:<task_key>` (префикс задаёт
  `IDEAL_TASK_TAG_PREFIX`). Каталог с `task_key` возвращает их по убыванию
  оценки. Если у задачи ещё нет цепочек или `task_key` не передан, цепочки
  похожих задач ищутся поиском.
- **Любая сохранённая цепочка**: каждая сохранённая версия разбирается без
  LLM. Для каждого шага `step_type=tool` IdeaL ищет `carl:<tool_name>` в том же
  пространстве или создаёт заглушку инструмента со статусом `unresolved`, и
  записывает:
  - `chain uses_tool tool` (с номерами шагов);
  - `step invokes_tool tool` (шаг — виртуальный узел внутри версии цепочки;
    его определяют версия цепочки, номер шага и отпечаток).

Итог прогона добавляет `chain derived_from idea` для каждой идеи на пути.
Запись связей идемпотентна. Если разбор упал, цепочка всё равно сохраняется,
а обратное заполнение при миграции повторит попытку.

## Граф

`GET /v1/ideal/graph?namespace=...` возвращает один общий граф:

| Типы узлов | Типы рёбер |
| --- | --- |
| `idea`, `tool`, `run`, `chain`, виртуальный `step` | События: `delivered`, `cited`, `path`, `result`. Связи: `uses_tool`, `invokes_tool`, `derived_from`, вычисляемое `contains_step`. |

Узлы идей и инструментов несут поля рейтинга (`gain_rate`, `strength`, число
выдач и применений). Для каждой цепочки граф берёт канал `evolved`, а если
его нет, то `latest`.

Библиотека Maestro рисует этот граф (см.
[Идеи в Библиотеке](/ru/ideal/maestro/library/)). У веб-интерфейса IdeaL свой
вид графа: кнопка **Graph** на вкладке IdeaL.

## Известные ограничения

- Заглушка `unresolved` вставляется без события сущности и начинается с
  `version_number=0`.
- Инструменты остаются привязанными к пространству. Между пространствами
  переносится только опыт, по `tool_key`.
- Разбор не связывает идеи с конкретными шагами по диффам мутаций.
