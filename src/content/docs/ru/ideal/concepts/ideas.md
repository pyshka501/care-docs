**Идея** — одно конкретное изменение цепочки. Мутатор может применить его
как написано, а оценка может его подтвердить или опровергнуть. В хранилище
идея — это `memory_card` GigaEvo Memory в некотором пространстве.

## Хорошая идея

| Хорошо | Не идея |
| --- | --- |
| «Разбить числовой ответ на два шага: сначала выписать все числа с подписью, единицей и строкой источника; затем считать только по этому списку». | «Улучшить промпт». |
| `when_to_use`: «Ответ требует арифметики над значениями из контекста». | `when_to_use`: «всегда» |
| Одно изменение, 1–3 предложения, назван затронутый шаг. | Несколько несвязанных изменений в одной карточке. |

Изменение одного параметра (temperature, `k`, порога) тоже не идея.
Извлечение на сервере такие изменения намеренно пропускает.

## Поля

| Поле | Где | Смысл |
| --- | --- | --- |
| `name` | `meta.name` и `content.name` | Короткий идентификатор, обычно английский `snake_case`. |
| `description` | `content.description` | Что изменить и как. Главный текст для поиска и мутаторов. |
| `when_to_use` | `meta.when_to_use` и `content.when_to_use` | Наблюдаемое условие. При заданном фокусе эволюция ищет сначала по нему. Retrieve возвращает значение из `meta`. |
| `status` | `content.status` | `active` или что-то другое. Выдаются только `active`. Maestro использует `archived`. |
| `tags` | `meta.tags` | Свободные теги. Maestro добавляет `topic:<тема>` и `origin:user`. |
| `origin` | `content.origin` | Кто создал: `manual`, `user` (форма Maestro), `skill`, `run_page`, извлечение. |
| `source` | `content.source` | Статья, название метода, «common practice» или прогон для извлечённых идей. |
| `topic`, `topic_label` | `content` | Группировка в Maestro: тема латиницей и подпись. |
| `content_hash` | `content` | Хеш нормализованного описания. Пишут засев и добавление со страницы прогона; если поля нет, вычисляется при чтении. |
| `variant_of` | `content` | У извлечённых идей, которые почти дублируют существующую. |
| `source_evidence` | `content` | Только у извлечённых идей: прогон, кандидат и класс результата, откуда идея взялась. |

## Статус: active и archived

- **active**: возвращается `retrieve` в обоих режимах, учитывается в обзоре.
- **archived**: `retrieve` её не возвращает. Версии и история рейтинга
  остаются. В Maestro на графе такая идея помечена «В архиве».

Жёсткого удаления в Maestro нет. В REST API есть `DELETE
/v1/memory-cards/{id}`. Это мягкое удаление: карточка пропадает из чтения, но
её события остаются в статистике озера. Лучше архивировать.

Для инструментов правило обратное: инструмент выдаётся, пока его `status`
не `archived`.

## Версии

Каждая правка — новая неизменяемая версия той же идеи (`PUT
/v1/memory-cards/{id}`). Нумерация версий начинается с 0.

- `GET /v1/memory-cards/{id}/versions` — список версий с `change_summary` и
  `parents`.
- `PUT` заменяет весь `content`. Передавайте все поля.
- С заголовком `If-Match: <etag>` запись отклоняется (HTTP 412), если идею
  изменили после вашего чтения. Maestro всегда так делает, поэтому двое не
  могут молча затереть правки друг друга.

Рейтинг привязан к id идеи, а не к версии. Правка сохраняет накопленный
опыт.

## Дубликаты и похожие идеи

Дубликаты разбавляют озеро: две копии делят опыт одной идеи. Проверки
зависят от того, кто пишет.

| Путь | Точный дубликат | Похожая идея |
| --- | --- | --- |
| `POST /v1/memory-cards` | Не проверяется. | Не проверяется. |
| Форма идеи в Maestro | То же нормализованное название в пространстве: запись отклоняется. Если двойник в архиве, предлагается вернуть его. | Пересечение слов названия, описания и `when_to_use` (оценка ≥ 0.35) плюс сильное совпадение в поиске каталога (relevance ≥ 0.5). Для сохранения нужно явно подтвердить «это другая идея». |
| Засев в веб-интерфейсе и `POST /v1/ideal/seed/propose` | Тот же хеш описания. | LLM озера даёт каждому кандидату вердикт `keep`, `rewrite` или `drop` и до трёх близких идей. |
| «Добавить идею» на странице прогона | Тот же хеш описания: возвращается как дубликат, не создаётся. | Не проверяется. |
| Извлечение на сервере | Тот же хеш описания: пропускается. | Почти дубликаты всё равно пишутся, как варианты (`variant_of`, описание заканчивается «Differs from …»). |
| `GET /v1/{entity_type}/duplicates` | Косинусная близость сохранённых эмбеддингов (по умолчанию ≥ 0.95). Нужен `ENABLE_VECTOR_SEARCH=true`, иначе 503. | То же. |

Проверка в Maestro также сообщает `non_english`, если латинских букв меньше
80%. Такую идею можно сохранить, но поиск будет находить её редко.

## Поиск

Идеи находит полнотекстовый поиск BM25 по их поисковым документам
(`name`, `description`, `when_to_use`). Конфигурация текста английская.
Последствия:

- русский (и любой неанглийский) текст не стеммится и не совпадает. Русский
  запрос обычно возвращает только добивку (`relevance: null`);
- совпадения слабее `RETRIEVE_MIN_RELEVANCE` (0.20) считаются ненайденными;
- перефразировки совпадают только по общим словам. Семантический поиск
  (`RETRIEVE_SEARCH_TYPE=semantic`) помогает с перефразировками. Но ему
  нужен образ с эмбеддингами и включённый векторный поиск. По умолчанию он
  выключен.

Переключатели описаны в разделе [Эксплуатация](/ru/ideal/api/operations/).
