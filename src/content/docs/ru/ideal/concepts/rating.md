IdeaL оценивает идею только по тому, что произошло, когда эволюция её
применила. Вручную идеи никто не оценивает. Здесь описаны входные данные и
два числа, которые видны везде: **доля улучшений** (gain rate) и **сила**
(strength).

## Подборки и контрольная группа

Перед каждой мутацией эволюция вызывает `POST /v1/retrieve` с
`mode=evolution`, `run_id` и `candidate_id`. IdeaL возвращает **подборку**:

- до `k` идей (по умолчанию 3) и не больше одного подходящего инструмента;
- выбранных сэмплированием Томпсона по рейтингу каждой идеи, с весом
  близости к запросу (`RETRIEVE_RELEVANCE_WEIGHT`, по умолчанию 0.7);
- либо, с вероятностью `IDEA_CONTROL_PROBABILITY` (по умолчанию 0.3),
  **пустую контрольную подборку**.

Записывается каждая подборка, в том числе пустая. Повторный вызов с теми же
`run_id` и `candidate_id` возвращает записанную подборку. Контрольная группа
позволяет IdeaL сказать: «мутации с идеями улучшали результат в X% случаев,
без идей — в Y%».

Запрос строится из `context.focus` (что улучшаем; можно список до четырёх
слабых мест). Без фокуса берётся `context.task_description`. Держите
`task_description` в одном-двух предложениях. Если передать весь промпт
эволюции, поиск ломается.

## Результаты мутаций

Когда дочерняя цепочка оценена, эволюция сообщает один результат:

```json
{"kind": "mutation", "run_id": "...", "candidate_id": "...",
 "delta": 0.04, "parent_score": 0.61,
 "cited_idea_ids": ["<идеи из этой подборки, которые реально применены>"],
 "metric": {"name": "accuracy", "higher_is_better": true,
            "lower_bound": 0, "upper_bound": 1, "min_delta": 0.01}}
```

- `delta` — оценка потомка минус оценка родителя, или `null` для
  невалидного потомка.
- В `cited_idea_ids` должны быть только идеи, которые мутация действительно
  использовала. Выданные, но не применённые идеи не получают ни заслуги, ни
  вины.
- `metric` необязателен. Он задаёт направление (`higher_is_better`), уровень
  шума (`min_delta`) и известный диапазон. IdeaL хранит последнее описание
  метрики для пары «пространство, задача».
- Повтор того же результата возвращает 200 вместо 201 и учитывается один раз.

Каждый результат с применёнными идеями попадает в один класс. Перед этим
`delta` разворачивается так, чтобы плюс всегда значил «лучше»:

| Класс | Условие |
| --- | --- |
| `gain` | `delta > min_delta` |
| `regression` | `delta < -min_delta` |
| `no_gain` | `abs(delta) ≤ min_delta` |
| `invalid` | `delta = null` |

## Доля улучшений

**Доля улучшений** (gain rate) — апостериорная вероятность того, что
применение идеи даст `gain`. Она берётся из бета-распределения. Поэтому новая
идея начинает около середины и сдвигается с накоплением данных. Одно
улучшение из одного применения даёт около 67%, а не 100%.

## Сила

**Сила** (strength) показывает размер эффекта по сравнению с другими
изменениями в той же задаче. Каждый валидный результат получает знаковый
процентиль в `[-1, 1]`: +0.8 значит «лучше 80% изменений в этой задаче».

- Если у всех валидных результатов задачи есть `parent_score` и известная
  граница, ранжируется доля оставшегося диапазона, которую удалось взять.
  Иначе ранжируется сам развёрнутый `delta`.
- Пока в задаче меньше 20 валидных результатов, процентили стягиваются к нулю
  множителем `n / 20`.
- Средняя сила идеи стягивается ещё раз по её собственному числу
  наблюдений: `n / (n + IDEA_STRENGTH_PRIOR_COUNT)` (по умолчанию 5).
- `no_gain` считается нулём, у `invalid` силы нет.

Маленьким числам доверять нельзя. Сводка `efficacy` («introduced in 4
children; gain rate 67%; mean strength +0.18; … (confident)») появляется
только после `IDEA_MIN_EVENTS` (по умолчанию 3) применений.

## Ключ задачи и перенос опыта

Опыт складывается на трёх уровнях:

1. то же пространство и тот же `task_key`;
2. тот же `task_key` в других пространствах;
3. общий опыт той же идеи везде.

Одна и та же идея в разных пространствах связывается через `content_hash`
нормализованного описания. Инструменты связываются через `tool_key`.
Верхние уровни работают как ограниченный априорный вклад. По мере роста
локального опыта он берёт верх. Если задачи расходятся в оценке идеи, общий
опыт ослабляется.

Если в retrieve нет `task_key`, уровни такие: пространство, затем общий.
Один `run_id` не может сменить ключ задачи посреди прогона (422).

**Ограничение.** Ключ задачи стабилен ровно настолько, насколько его делает
стабильным вызывающая сторона. Maestro строит его из хеша описания задачи
цепочки (см. [Эволюция](/ru/ideal/maestro/evolution/)). Переформулированная
задача получает новый ключ и начинает без локального опыта. Переносятся только
уровни 2 и 3.

## Итог прогона

В конце прогона эволюция один раз сообщает лучшую цепочку:

```json
{"kind": "run", "namespace": "...", "task_key": "...", "run_id": "...",
 "best_chain": {...}, "best_fitness": 0.65,
 "path_idea_ids": ["<идеи, применённые в родословной лучшей цепочки>"]}
```

IdeaL сохраняет `best_chain` как `chain` с тегом `task:<task_key>` и её
оценкой. Поиск по каталогу сможет предложить её на той же задаче. Каждая
идея из `path_idea_ids` получает **победу на пути** и связь `derived_from` с
цепочкой. Атрибуция наивная: считается каждая идея в родословной.

## Подсказанные идеи

В идущем прогоне человек может подсунуть идею: она попадает в каждую
следующую подборку, пока какая-нибудь мутация её не применит (группа
`forced`, никогда не контроль). Такие мутации видны в ленте прогона, но не
учитываются в рейтинге идей и в сравнении «с идеями против контроля».

## Извлечённые идеи

При `IDEAL_EXTRACTION_ENABLED=true` и настроенной LLM озера результаты с
полем `change: {diff, rationale}` превращаются в новые активные идеи во время
и после прогона. Их `source_evidence` указывает на реальные записи
результатов и учитывается в той же доле улучшений и силе. Изменения только
параметров и изменения, которые реализуют уже существующую идею, пропускаются.
По умолчанию извлечение выключено.

## Где видны числа

| Место | Показывает |
| --- | --- |
| Maestro, Библиотека → Идеи | Рейтинг (доля улучшений), сила, выдачи, применения, успехи, победы на пути. |
| Maestro, радар прогона | Эффект каждой выданной идеи в прогоне, идеи против контроля. |
| Веб-интерфейс IdeaL, вкладка IdeaL | Обзор, задачи, таблица идей с `efficacy`, прогоны. |
| Страница прогона (`run_url`) | Радар, кривая лучшей оценки, группы, лента мутаций. |
