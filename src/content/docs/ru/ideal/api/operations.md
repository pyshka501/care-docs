IdeaL работает в составе стека GigaEvo Memory. Всё ниже управляется
`Makefile` в корне и `deploy/docker-compose.yml` (проект Compose
`gigaevo-memory`) репозитория `gigaevo-memory`, ветка `dev`.

## Сервисы

| Сервис | Роль | Наружу |
| --- | --- | --- |
| `nginx` | Единая точка входа. `/` → веб-интерфейс, `/api/` → API (префикс снимается). | `${MEMORY_HTTP_BIND_ADDRESS:-0.0.0.0}:${MEMORY_HTTP_PORT:-8000}` |
| `memory-api` | Приложение FastAPI (REST и `/mcp`). | Loopback `:8002` для отладки. |
| `web-ui` | Интерфейс Gradio. | Loopback `:7861` для отладки. |
| `memory-migrate` | Разовый запуск: Alembic `upgrade head`, затем засев и обратное заполнение связей. Выполняется до старта API. | Нет. |
| `postgres` | `pgvector/pgvector:pg16`. | Только внутри. |
| `redis` | Pub/sub событий, счётчики прогонов. | Только внутри. |

На хосте без файрвола задайте `MEMORY_HTTP_BIND_ADDRESS=127.0.0.1` и
поставьте перед стеком обратный прокси с TLS.

## Окружение

Скопируйте `deploy/.env.example` в `deploy/.env`. Без него Compose не
стартует.

### Основное

| Переменная | По умолчанию | Примечание |
| --- | --- | --- |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | `memory`, `memory_dev_password`, `memory` | Смените пароль. |
| `POSTGRES_DSN` | соответствует значениям выше | DSN asyncpg для API. |
| `REDIS_URL` | `redis://redis:6379/0` | |
| `API_SECRET_KEY` | `dev-secret-key-change-in-production` | **Смените.** Подписывает ссылки на прогоны и шифрует ключи, выпущенные администратором. Смена позже делает недействительными все ссылки на прогоны и нечитаемыми сохранённые ключи. |
| `API_ROOT_PATH` | `/api` | Публичный префикс; из него строится `run_url`. |
| `AUTH_REQUIRED` | `false` | В рабочей среде ставьте `true`. Настройка во вкладке Admin важнее. |
| `CORS_ALLOWED_ORIGINS` | `*` | Для браузерных клиентов перечислите источники явно. |
| `OIDC_ENABLED`, `OIDC_ISSUER`, `OIDC_AUDIENCE`, … | выключено | Необязательная авторизация по токену. |

### IdeaL

| Переменная | По умолчанию | Эффект |
| --- | --- | --- |
| `IDEAL_SEED_NAMESPACE` | `demo` в примере, пусто в коде | Пространство, куда попадают 40 начальных идей и стартовая цепочка. Пусто — без засева. |
| `IDEAL_PUBLIC_API_URL` | пусто | Внешний адрес API для промпта «Connect your agent»; пусто — адрес браузера + `/api`. |
| `IDEAL_UI_LANGUAGE` | `ru` | Язык страницы прогона (`ru` или `en`). `ru` переводит текст страницы через LLM озера в фоне; сохранённые данные остаются английскими. |
| `IDEA_CONTROL_PROBABILITY` | `0.3` | Доля пустых подборок эволюции для сравнения. |
| `IDEA_MIN_EVENTS` | `3` | Сколько применений нужно до показа `efficacy`. |
| `IDEA_STRENGTH_PRIOR_COUNT` | `5` | Стягивает среднюю силу идеи к нулю. |
| `IDEAL_TASK_TAG_PREFIX` | `task:` | Тег, который связывает цепочки с задачей. Смена прячет существующие цепочки задач. |
| `IDEAL_EXTRACTION_ENABLED` | `false` | Извлекать новые идеи из сообщённых изменений. Нужна LLM озера. |
| `IDEAL_EXTRACTION_MAX_DIFF_CHARS`, `…_MAX_RATIONALE_CHARS` | `20000`, `4000` | Лимиты хранения для `change`. |

### Поиск

| Переменная | По умолчанию | Эффект |
| --- | --- | --- |
| `RETRIEVE_DEFAULT_K` | `3` | Число идей, если `k` не передан. |
| `RETRIEVE_TOOL_LIMIT` | `1` | Подходящих инструментов на один retrieve. |
| `RETRIEVE_POOL_SIZE` | `10` | Из скольких кандидатов выбирает эволюция. |
| `RETRIEVE_RELEVANCE_WEIGHT` | `0.7` | Вес близости к запросу против полезности (`0..1`). |
| `RETRIEVE_SEARCH_LIMIT` | `100` | Глубина поиска. |
| `RETRIEVE_SEARCH_TYPE` | `bm25` | `bm25` или `semantic` (BM25 + векторы, слияние по рангу). |
| `RETRIEVE_MIN_RELEVANCE` | `0.20` | Более слабые совпадения BM25 считаются ненайденными. |
| `RETRIEVE_MIN_SIMILARITY` | `0.434` | Более слабые косинусные совпадения считаются ненайденными (semantic). |
| `RETRIEVE_QUERY_MAX_TERMS` | `64` | Сколько слов берётся из контекста. |

Семантическому поиску нужны все три условия: образы, собранные с
`WITH_EMBEDDINGS=true` (пересборка), `ENABLE_VECTOR_SEARCH=true` и
`RETRIEVE_SEARCH_TYPE=semantic`. Эмбеддинги: `EMBEDDING_PROVIDER`
(`sentencetransformers`, `openai`, `huggingface`), `EMBEDDING_MODEL` (по
умолчанию `all-MiniLM-L6-v2`), `VECTOR_DIMENSION` (384). Семантический поиск
помогает с перефразировками. Русский текст он с английской моделью по
умолчанию находимым не делает.

### LLM озера

Используется извлечением, предложениями засева, семантической
дедупликацией, переводом страницы прогона и названиями секторов.

| Переменная | Пример значения | Примечание |
| --- | --- | --- |
| `IDEAL_LLM_API_URL` | `https://inference.airi.net/v1` | Любой OpenAI-совместимый адрес. В коде не задан. |
| `IDEAL_LLM_API_KEY` | — | Нужен для любой функции LLM. |
| `IDEAL_LLM_MODEL` | `Qwen/Qwen3.8-27B` | Основная модель. |
| `IDEAL_LLM_FAST_MODEL` | — | Быстрая модель для предложений на странице прогона; если не задана, берётся основная. |
| `IDEAL_LLM_DISABLE_THINKING` | `false` | Пропускать фазу рассуждений на vLLM/Qwen3, чтобы укладываться в таймауты. |

Без адреса, ключа и модели функции LLM выключены: предложения засева
отвечают 503, страница прогона показывает исходный текст, секторы берут
названия из тегов. Модели можно переключить в веб-интерфейсе (вкладка IdeaL →
LLM models); сохранённый выбор важнее окружения.

## Миграции

`make up` применяет миграции сам через `memory-migrate`. Таблицы IdeaL
появляются в миграциях `006`–`017` (события, метрики переноса, связи,
извлечение, подсказки в прогонах, поисковые документы `when_to_use`, кэш
перевода интерфейса, настройки, пространства ключей, bootstrap admin,
зашифрованные ключи).

| Команда | Что делает |
| --- | --- |
| `make migrate` | Запустить `memory-migrate` (upgrade head + засев + обратное заполнение). |
| `make migrate-down` | Откатить одну ревизию. |
| `make migrate-check` | Тесты целостности цепочки миграций, затем upgrade → downgrade -1 → upgrade. Та же проверка, что в CI. |
| `make db-reset` | Удалить и пересоздать схему (сначала спрашивает). |

## Резервные копии

```bash
make backup                                # ./backups/gigaevo-memory-<UTC>.sql.gz
S3_BUCKET=my-bucket make backup            # ещё и загрузить в s3://my-bucket/gigaevo-memory/backups/
make backup-dry-run                        # только показать команды
```

Переменные: `BACKUP_DIR`, `POSTGRES_USER`, `POSTGRES_DB`, `COMPOSE_FILE`,
`COMPOSE_PROJECT`, `S3_BUCKET`, `S3_PREFIX`. Запускайте по расписанию через
cron или таймер systemd. События прогонов и рейтинги хранятся в Postgres.
В Redis только счётчики и pub/sub, его резервировать не нужно.

## Ключи

```bash
make create-key OWNER=alice [SCOPES=...] [LABEL="..."] [EXPIRES_DAYS=30]
```

Открытый текст печатается один раз, в базе хранится хеш SHA-256. Остальное
выпускайте и настраивайте во вкладке Admin. См.
[Пространства и ключи](/ru/ideal/concepts/namespaces-and-keys/).

## Здоровье и метрики

- `GET /health`: Postgres, Redis, пул соединений, число сущностей, режим `auth`.
- `GET /metrics`: метрики Prometheus (запросы, задержка, число сущностей).

## Чек-лист для рабочей среды

- Включите `AUTH_REQUIRED=true` (или переключатель в Admin), задайте
  надёжные `API_SECRET_KEY` и пароль Postgres.
- Отзовите ключ `bootstrap admin`, если у вас нет его открытого текста.
- Привяжите nginx к loopback и завершайте TLS перед ним.
- Задайте `CORS_ALLOWED_ORIGINS` явно.
- Храните ссылки на прогоны как секреты: они дают просмотр прогона и
  подсказку идей.
- Настройте регулярный `make backup`.
- Помните: любой, кто может писать в пространство, влияет на мутации
  прогонов, которые его читают.
