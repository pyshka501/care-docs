Заметки по версиям. Полная версия лежит в репозитории:
[`RELEASE.md`](https://github.com/AIRI-MAESTRO/carl/blob/v0.5.2/RELEASE.md).
0.5.0, 0.5.1 и 0.5.2 вышли на PyPI как `mmar-carl` в один день, 2026-11-09.
Последняя ставится так: `pip install 'mmar-carl==0.5.2'` (Python 3.12+).

:::note
Приложение Maestro пока работает на более старой закреплённой сборке CARL, а не
на этих релизах. См.
[какой CARL запускает Maestro](/ru/carl/care-integration/overview/#какой-carl-запускает-maestro).
:::

## 0.5.2

Добавлен [шаг terminate](/ru/carl/steps/terminate/). Формат цепочки 14 → 15.

- `TerminateStepDescription` (`terminate`) с `TerminateStepConfig`: ровно одно
  из `output` (литеральное JSON-значение, `null` тоже считается) или
  `output_source` (ссылка `$`; неразрешимая ссылка валит шаг), плюс `reason`.
- Текущий батч сначала доходит до конца, включая соседей, которые ждали
  свободного воркера. Если успешных terminate-шагов несколько, ответ выбирает
  шаг с меньшим номером. Последующие шаги помечаются пропущенными, новых
  действий планировщика, итераций циклов и RE-PLAN этот батч не запускает.
- Уже случившиеся сбои по-прежнему влияют на итог. Отмена хостом и fail-fast
  важнее остановки. Номер шага и причина пишутся в
  `result.metadata["terminated"]` и в трассу. `ReasoningResult.get_final_output()`
  возвращает выбранный ответ даже после обрезки истории.

**Миграция с 0.5.1.** Поднимайте сохранённый JSON через
`ReasoningChain.from_dict(ReasoningChain.migrate(raw))`, ступень 15 ничего не
переписывает. Читатели старше 0.5.2 формат 15 отклоняют. Снимок, в котором
terminate-шаг уже выполнился, нельзя продолжить дальше него.

## 0.5.1

Добавлен [шаг decision](/ru/carl/steps/decision/). Формат цепочки 13 → 14.

- `DecisionStepDescription` (`decision`) задаёт decision-модели
  типизированные вопросы об одном текстовом или JSON-состоянии: `predicate`
  (вероятность с порогом), `choice` (одна из 2–255 опций) и `score` (упорядоченная
  шкала из 2–10 уровней). `fallback` и `min_confidence` у вопроса обрабатывают
  отказы и низкую уверенность, иначе шаг падает.
- Адаптеры для OpenRouter Decisions и прямых Decisions API OpenAI и Azure
  OpenAI с одной формой ответа в `result_data["answers"]`. Расход и стоимость
  пишутся, если провайдер их сообщает.
- Ответы можно писать в память (`output_memory_key`, пространство `decision`)
  для условной маршрутизации. Шаблоны состояния используют явный
  `input_mapping` и лимит по байтам.
- **Разрешение хоста.** `ReasoningContext.decision_endpoints` разрешает точный
  URL запроса и переменную окружения с ключом для каждого провайдера. Ни
  разрешение, ни ключ в JSON цепочки не попадают. У `PreflightReport`
  появились `required_decision_credentials` / `missing_decision_credentials`.
- Временные ошибки повторяются в пределах `max_retries`, тела ошибок провайдера
  в ошибки шага не попадают. `httpx` теперь базовая зависимость.

**Миграция с 0.5.0.** Поднимайте JSON через `migrate()`, ступень 14 ничего не
переписывает. Перед запуском decision-шага выдайте разрешение на эндпоинт и
ключ. Цепочкам без decision-шагов новая настройка не нужна. Воспроизведение
трассы исполнения decision-шаги не поддерживает. Живые проверки шли через
OpenRouter, у прямых адаптеров OpenAI и Azure только офлайн-тесты.

## 0.5.0

Релиз про совместную работу агентов и управление исполнением. Формат цепочки
9 → 13.

### Новые типы шагов

| Класс | `StepType` | Назначение |
| --- | --- | --- |
| [`ClaudeCodeStepDescription`](/ru/carl/steps/claude-code/) | `claude_code` | Делегировать работу локальному Claude Code CLI. |
| [`CodexStepDescription`](/ru/carl/steps/codex/) | `codex` | Делегировать работу локальному агенту Codex SDK. |
| [`SelectionStepDescription`](/ru/carl/steps/selection/) | `selection` | Выбрать элементы коллекции без вызова LLM. |
| [`PlannerStepDescription`](/ru/carl/steps/planner/) | `planner` | Выбрать и упорядочить ограниченный набор объявленных действий-инструментов. |

### Локальные агенты для кода

- Шаги Claude Code и Codex работают, только если доверенный хост выставил
  `ReasoningContext(allow_local_agent_execution=True)`. Загрузка цепочки этого
  разрешения не даёт.
- Шаги умеют продолжать сессию или тред и сохранять его id для следующих шагов,
  оба проверяют структурированный вывод.
- Переопределения `env` у Claude Code больше не пишутся в JSON цепочки.

### Ограниченное планирование

- Планировщик выбирает id действий, а сами действия, их аргументы и бюджет
  задаёт цепочка. Выбранные действия выполняются как обычные tool-шаги до
  зависимых от планировщика шагов.
- `on_step_event(..., "planner_actions_scheduled", payload)` сообщает
  выданные номера шагов.
- Полный, прошедший схему план переживает сбой транспорта в самом конце.
  Учёт токенов включает расход от совместимых стриминговых провайдеров.

### Инструменты и навыки из Git

- [`GitToolSource`](/ru/carl/steps/tool-discovery/#инструменты-из-закреплённого-коммита-git)
  регистрирует функции с `@carl_tool` или одну названную функцию из Git.
  Инструменты и навыки можно закрепить на коммите и сверять с SHA-256 файлов,
  в том числе при попадании в кэш.
- AgentSkill читает файлы только внутри каталога навыка и подготовленной
  рабочей области. С `trust_policy="sha_pinned"` шаг проверяет те же байты
  `SKILL.md`, которые разбирает.

### Совместная работа и эволюция

- Подцепочки handoff, агенты supervisor и базовые шаги сэмплинга переживают
  круг через JSON (формат 11). Трассы по агентам записывают вложенные прогоны
  и запасные пути агрегации.
- Записи в разные ключи одного пространства имён переживают слияние
  результатов параллельных шагов.
- [Примитивы EvoC](/ru/carl/evolution/overview/#примитивы-evoc): каталог шагов,
  проверка спецификаций, мутации графа и полей, контракты инструментов-кода,
  помощники оценки, дескрипторы запусков, Парето.
- `validate_spec` проверяет, что явные входы `$steps.N` указывают на
  объявленных предшественников; помощники мутаций проверяют это до принятия
  правки.

### Входы, планирование и сбои

- Входы хоста идут через `ReasoningContext.runtime_input` и явные ссылки.
  Промпты structured output и ввода человека могут брать только нужные поля.
  Отсутствующий обязательный вход инструмента валит шаг до вызова.
- Включаемый `fail_fast` прекращает запуск новых шагов после окончательного
  сбоя. Пауза подтверждается, когда активные шаги закончились; возобновление
  отпускает очередь, не повторяя завершённые шаги.
- У параллельных запусков свои кэши шагов и бюджеты вставок. Активные шаги
  делят оставшийся дедлайн цепочки.
- Экспериментальная [`execute_eager_tools()`](/ru/carl/steps/tool/#ранний-запуск-инструментов-экспериментально)
  запускает инструмент, как только его зависимости успешно завершились.
- После переключения на запасной инструмент `StepExecutionResult.tool_name`
  называет тот, что реально отработал. JSON-текст результата раскладывается в
  `result_data`. Упавшие встроенные цепочки и MCP-ответы с `isError` валят шаг.
  Ограничения по тегам инструментов действуют и на основной, и на запасной
  вызов.
- Исполнитель больше не закрывает одолженные LLM-клиенты. Ответ без текста,
  исчерпавший бюджет токенов, бросает `LLMTokenLimitError`. Extra `mcp`
  ограничен SDK 1.x.

### Ломающие изменения

1. **Формат цепочки 9 → 13.** Формат 12 сохраняет `fail_fast`,
   `max_injections`, `memory_schema` и `step_groups`, формат 13 добавляет
   планировщик. Старые читатели отклоняют новые снимки с
   `ChainFormatNewerError`.
2. **Локальным агентам нужно разрешение хоста.** Приложения с шагами Claude
   Code или Codex должны выставить `allow_local_agent_execution` в доверенном
   контексте хоста.
3. **Сбои инструментов влияют на статус цепочки.** Код, который принимал
   MCP-ошибку или упавшую встроенную цепочку за успешный шаг, должен
   обрабатывать сбой шага.
4. **Формат ответа задаёт шаг.** Стандартные английская и русская обёртки
   промпта несут только инструкции и контекст. Нужный формат вывода задайте в
   шаге или передайте явный `PromptTemplate`.

### Миграция с 0.4.0

1. Поднимайте сохранённый JSON через
   `ReasoningChain.from_dict(ReasoningChain.migrate(raw))`. Если в старом файле
   не было вложенного субагента, подключите его топологию из исходника.
2. Разрешите локальных агентов для доверенных сценариев и передавайте
   переопределения окружения Claude Code во время запуска.
3. Старые цепочки Maestro: миграция убирает устаревшие запасные значения ввода
   человека, а отсутствие провайдера и таймауты дают типизированные неуспешные
   исходы.

Подробности: [миграция](/ru/carl/serialization/migration/#обновление-хоста-до-05x).

### Известные ограничения (0.5.2)

- Путь `from_json()` / `load()` по умолчанию восстанавливает шаги `llm`,
  `tool`, `mcp`, `memory`, `transform`, `conditional`, `structured_output`,
  `command` и `shell_session` как legacy `StepDescription`. Для типизированных
  объектов используйте `from_dict_typed()`.
- `StepDescription.to_typed_step()` теряет `retry_max` и `timeout`.
- `ChainMutator` игнорирует `StepDescriptionBase.frozen`, его учитывают только
  помощники `mmar_carl.meta`.
- `ClaudeCodeStepConfig.env` из загружаемого JSON принимается, хотя
  `to_dict()` его никогда не пишет.

## 0.4.0

Релиз исполнения (2026-08-27). Правило релиза: сериализованная цепочка это
вход, а не источник полномочий. Разрешения хост выдаёт во время запуска.

- **Семь типов шагов**: `agent` (ограниченный цикл с инструментами и явным
  `finish`), `code` (одна точная сгенерированная функция Python `run(inputs)`
  в профиле песочницы, #23), `wait` (таймер, событие, any-of, #19), `map`
  (ограниченный упорядоченный fan-out по JSON-массиву, #22), `command_plan`,
  `command` (argv через среду навыков, бывший `bash`) и `shell_session`.
- **Полномочия хоста**: `CommandPolicy`, `CommandCapabilityRegistry`,
  `NetworkEnforcer`, `CodeExecutionPolicy` живут в `ReasoningContext` и
  никогда не пишутся в JSON цепочки.
- **Цепочка как инструмент** (#21): `ChainToolDefinition` встраивает снимок
  цепочки как изолированный ограниченный инструмент. Результат приходит как
  `ChainToolOutcome`.
- **Жизненный цикл HumanInputStep** (#20, ломающее изменение):
  `fallback_value` удалён. Провайдер хоста имеет вид
  `async (HumanInputRequest) -> HumanInputResponse`.
  `as_human_input_outcome()` возвращает типизированный статус.
- **Structured output проверяется** по JSON Schema. Неверные схемы и
  удалённые `$ref` падают до вызова провайдера. `jsonschema` стал основной
  зависимостью.
- **Телеметрия LLM**: `get_response_with_tools_and_usage()`. Кассеты пишут
  usage. Битые аргументы tool call сохраняются как исходная строка.
- **Сериализация**: формат цепочки 1 → 9 с лестницей миграций
  (`ReasoningChain.migrate`). `loop_back_to`, `loop_config` и `triggered_by`
  сохраняются.
- **Переносимые артефакты** (`ArtifactInput` / `ArtifactOutput` /
  `ArtifactRecord`) и отчёты о применении ограничений в средах навыков.
