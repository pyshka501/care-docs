Чтобы мемоизировать результат шага, присвойте полю `cache` объект `StepCache`.
Перед выполнением шага DAG-исполнитель заглядывает в кэш в памяти. При попадании
он возвращает сохранённый результат **без вызова LLM или инструмента**.

Кэш живёт в `DAGExecutor` и очищается в начале каждого `chain.execute()`. Внутри
одного запуска его делят все батчи. Это помогает [циклам](/ru/carl/steps/loops/),
которые снова видят те же входы. Между запусками ничего не сохраняется.

## StepCache

| Поле | Тип | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `ttl` | `int \| None` | `None` | Время жизни в секундах (≥ 1). `None` = в пределах запуска не истекает. |
| `key_fn` | `Callable[[ReasoningContext], str] \| None` | `None` | Своя функция ключа кэша. |

**Ключ по умолчанию:** `f"{step.number}:{context.outer_context[:256]}"`, то есть
номер шага плюс первые 256 символов `outer_context`. История, память и входы шага
в него не входят. Внутри одного запуска `outer_context` обычно не меняется. Поэтому
шаг с ключом по умолчанию попадает в кэш начиная со второго выполнения, даже если
то, что он читает, изменилось. Если результат зависит от чего-то ещё, задайте
`key_fn`.

Если `key_fn` бросает исключение, используется ключ по умолчанию.

## Пример

```python
from mmar_carl import LLMStepDescription, StepCache

LLMStepDescription(
    number=2,
    title="Classify intent",
    aim="Classify the user intent.",
    cache=StepCache(
        ttl=300,
        key_fn=lambda ctx: "2:" + ctx.outer_context[:512],
    ),
)
```

## Правила

- Для попадания нужна неистёкшая запись по вычисленному ключу.
- Сохраняются только успешные результаты.
- Попадание воспроизводит сохранённые `result`, `result_data`, `token_usage` и
  запись истории, а также ставит `profiling["cache_hit"] = True`. Побочные эффекты
  исходного выполнения, например записи в память, **не** воспроизводятся.
- `cache` исключается из сериализации (`to_dict` / `to_json`), как и `key_fn`.
  После загрузки цепочки из JSON подключите кэширование заново.

:::caution
Свой ключ используется как есть, номер шага к нему не добавляется. Два шага, чьи
`key_fn` возвращают одинаковую строку, делят одну запись, и второй шаг получает
результат первого. Включайте номер шага в свои ключи, как в примере выше.
:::

## Шаги, которые не принимают `cache`

Эти типы шагов выдают ошибку валидации, если задан `cache`. Их выполнение имеет
побочные эффекты или зависит от состояния, которое есть только во время выполнения:

| Шаг | Причина |
| --- | --- |
| `command` | Выполнение команды может иметь побочные эффекты. |
| `shell_session` | Выполнение shell может иметь побочные эффекты. |
| `command_plan` | Его реестр возможностей хоста существует только во время выполнения. |
| `claude_code` | Агент может читать или менять рабочую папку. |
| `codex` | Ход Codex может читать или менять рабочую папку. |

Все остальные типы шагов `cache` принимают. Среди них есть шаги с возможными
побочными эффектами: `tool`, `mcp`, `agent`, `code`, `map` и `human_input`.
Кэшируйте их, только если вам действительно нужно повторить прежний результат.
