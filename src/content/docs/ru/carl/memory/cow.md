Шаги одного параллельного батча работают каждый на своей копии контекста.
Память в этой копии это представление **copy-on-write** над родителем. Пока
шаг ничего не трогает, ничего не копируется. После батча обратно сливается
только то, что шаг действительно изменил.

## Что видит шаг

- Каждый шаг видит память в состоянии **на начало своего батча**.
- Записи шага **не видны** соседям по батчу, только следующим батчам.
- При чтении пространства имён копируется словарь, а не значения.
  Изменяемое значение (список, словарь) глубоко копируется при первом чтении
  шагом. Поэтому `memory_append` или правка на месте внутри параллельного шага
  никогда не меняют родителя или соседа.
- Зарегистрированные инструменты общие, они передаются по ссылке. Их должно
  быть безопасно вызывать одновременно.

## Как сливаются записи

Хранилище запоминает, какие ключи шаг **записал** или **удалил** (чтение не
считается). После батча CARL сливает изменения по шагам в порядке их
объявления:

1. Сначала удаления, потом записи, по ключам.
2. Шаг, который только читал пространство имён, ничего не сливает. Он не
   может откатить запись соседа.
3. Два шага пишут **разные** ключи одного пространства имён: оба значения
   сохраняются.
4. Два шага пишут **один** ключ (запись/запись, запись/удаление, два append
   в один список): побеждает шаг, объявленный позже. Append не объединяются.
   Порядок не зависит от `max_workers` и времени выполнения.
5. Каждое сливаемое значение проверяется по
   [`memory_schema`](/ru/carl/memory/schema/) контекста. Нарушающее значение
   отбрасывается, а записавший его шаг помечается упавшим.
6. Изменения памяти упавшего шага не сливаются. Исключение шаг `map`: его
   итоговый выход сливается, даже если часть элементов упала.

Пример, проверенный на 0.5.0: два параллельных шага памяти пишут `k1` и `k2`
в пространство имён, где уже есть `k1 = "old"`. Итог:
`{"k1": "v1", "k2": "v2"}`.

## Профилирование

Размеры памяти и истории по шагам пишутся в `StepExecutionResult.profiling`
(`memory_bytes_after`, `history_bytes_after`, `history_bytes_added`). Сводку
даёт `result.get_profiling_summary()`.
