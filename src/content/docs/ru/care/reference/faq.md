## Приложение

### Приложение не запускается из исходников

Запуску из исходников нужен закреплённый runtime харнесса. В сообщении об
ошибке сказано, чего не хватает. Используйте `Maestro.app` или укажите
собранный runtime флагами для разработчиков из `maestro app --help`. Если
версия харнесса отличается от закреплённой, запуск тоже останавливается.

### «The current chat model is unavailable for this chain operation»

Так приложение сообщает, что модель чата для этой операции недоступна.
Генерация, запуск и исправление используют модель чата сессии через
приватный мост. Проверьте **Настройки → Модель чата**: у провайдера есть ключ,
и в этом чате выбрана модель. Отдельный ключ Maestro никогда не подставляет.

### Я задал модель в Настройки → MAESTRO, а генерация идёт другой

Так и должно быть. В приложении генерация использует **модель чата**.
Провайдер, URL, модель и ключ из блока *Chain generation* на странице MAESTRO
настраивают только CLI, TUI и старый workbench. Заголовок страницы здесь
вводит в заблуждение. См. [Настройки](/ru/care/app/settings/).

### Сохранил настройки, но ничего не изменилось

После каждого сохранения на странице MAESTRO нужно **полностью закрыть и
открыть** приложение.

### Библиотека пишет, что память не отвечает

Строка состояния вверху Библиотеки говорит, нет ли ключа или не отвечает
сервер. Проверьте **Memory base URL** (облачному хранилищу нужен API-префикс,
например `https://…/api`) и **Memory API key**. Затем нажмите ↻.

### Идеи, Наборы данных или Инструменты и навыки просят открыть сессию

Эти разделы работают от имени открытой сессии. Откройте любую сессию в
боковой панели и вернитесь в Библиотеку.

### Активность пустая после перезапуска

Список в процессе начинается заново при каждом запуске. Если IdeaL включён,
прогоны эволюции, которые хранит IdeaL, по-прежнему видны вверху панели.

### Платная работа идёт без вопроса

У сессии режим **Полный доступ**, он никогда не спрашивает. Выберите другой
режим, чтобы окно вернулось. См. [Подтверждения](/ru/care/app/confirmations/).

### «MAESTRO_APPROVAL_UNAVAILABLE»

Приложение не смогло прочитать настройку подтверждений сессии и отклонило
платное действие. Ничего не запускалось. Повторите. Если не помогает,
перезапустите приложение.

### Эволюцию нельзя поставить на паузу

Верно: современные прогоны эволюции можно только отменить.

### Мой набор данных нельзя использовать для эволюции

Нужны минимум два проверенных примера поисковой части и поддерживаемый
оценщик. Наборы *задач с инструментами* для эволюции пока не подходят. См.
[Данные для эволюции](/ru/care/workflows/data-generation/).

## TUI и CLI

### Production всё время возвращается в Interactive

Production нужна Memory. Задайте `CARE_MEMORY__BASE_URL` (и
`CARE_MEMORY__API_KEY`, если сервер его требует). Проверьте
[`maestro doctor`](/ru/care/cli/setup/).

### Вместо запуска цепочки — подсказка об установке

CARL — необязательный extra для CLI и TUI. Установите его:

```bash
uv sync --extra carl     # или: pip install 'maestro-care[carl]'
```

Maestro импортирует внешние модули лениво, поэтому минимальная установка
запускается, а подсказка называет недостающий extra.

### Ошибки модели (401 / 403 / 429)

Они приходят от провайдера:

- **401**: ключа нет или он неверный. В CLI/TUI исправьте
  `CARE_MAGE__API_KEY` или снова выполните [`maestro init`](/ru/care/cli/setup/);
  в приложении исправьте ключ в **Настройки → Модель чата**.
- **403**: модель или маршрут недоступны для вашего ключа. Выберите другую
  модель.
- **429**: ограничение частоты. Подождите или смените модель или провайдера.

### Первый запуск TUI открывает настройки

Так и должно быть, если нет `~/.config/care/config.toml`.

### Ключи лежат открытым текстом

`maestro init` пишет ключ в `.env` открытым текстом. Перенесите ключи из
`~/.config/care/config.toml` в хранилище ОС командой
[`maestro migrate-secrets`](/ru/care/cli/setup/).

### Проверка состояния

```bash
maestro doctor              # окружение, конфигурация, extras, живые проверки
maestro doctor --no-probes  # без сетевых проверок (офлайн / CI)
```
