Maestro — пользовательский слой над стеком из отдельных модулей. Каждый
модуль отвечает за свой этап жизни цепочки.

```mermaid
flowchart TB
    User([Вы]) --> App
    subgraph App["Приложение Maestro"]
        Harness["Харнесс Maestro<br/>агент в чате · сессии · подтверждения · задачи"]
        Plugins["Плагины Maestro<br/>Мои агенты · панель IdeaL · Активность · карточки · Настройки"]
        Tools["Инструменты Maestro<br/>план · написание · генерация · запуск · исправление · сохранение<br/>документы · данные · мастерская · идеи · эволюция · настройки"]
        Gateway["Шлюз IdeaL<br/>локальный, 127.0.0.1"]
        Harness --> Tools
        Plugins --> Tools
        Plugins --> Gateway
    end
    Gateway -->|веб-страницы IdeaL| IdeaL
    Tools -->|задача, модель для цепочек| MAGE["MAGE<br/>генератор цепочек"]
    MAGE -->|цепочка CARL| Tools
    Tools -->|цепочка + вход, модель для цепочек| CARL["CARL 0.5.0<br/>исполнитель цепочек"]
    CARL -->|результат| Tools
    Tools <-->|цепочки · карточки · инструменты · навыки| Memory[("GigaEvo Memory")]
    Tools <-->|идеи · граф · радар| IdeaL[("IdeaL<br/>в Memory")]
    Tools -->|исходная цепочка + набор данных| Platform["Платформа эволюции<br/>GigaEvo Platform"]
    Platform <-->|подборки идей · результаты| IdeaL
```

| Часть | Пакет / сервис | Роль |
| --- | --- | --- |
| **Maestro** | `maestro-care` (импорт `care`) | Приложение (харнесс и плагины Maestro), слой инструментов, TUI и CLI. |
| **Харнесс Maestro** | входит в `Maestro.app` | Постоянный агент в чате: сессии, выбор модели, инструменты, подтверждения, фоновые задачи. |
| **MAGE** | `mmar-mage` | Превращает описание задачи в цепочку CARL. Работает внутри Maestro. В приложении это запасной вариант к агенту чата, который пишет цепочку сам. |
| **CARL** | `mmar-carl` | Выполняет цепочки: типизированные шаги, зависимости, инструменты, MCP, навыки. См. [CARL](/ru/carl/getting-started/overview/) и его [журнал изменений](/ru/carl/reference/changelog/). |
| **GigaEvo Memory** | `gigaevo-client` + сервер Memory | Хранит цепочки (с версиями), карточки памяти, инструменты и навыки. |
| **IdeaL** | часть сервера Memory | Идеи по пространствам, их рейтинг по итогам эволюции, графы прогонов и радар. См. [IdeaL](/ru/ideal/getting-started/overview/). |
| **Платформа эволюции** | GigaEvo Platform (HTTP) | Эволюционирует цепочку на наборе данных со своими моделями мутации и валидации. |

## Внутри приложения

- **Харнесс** ведёт разговор: чат, выбор модели, очередь следующих
  сообщений, отмена, окно подтверждения и список задач.
- **Инструменты** Maestro работают в отдельном локальном процессе, который
  приложение запускает и останавливает вместе с окном. Они держат правила
  цепочек: артефакты, закреплённые по хэшу, входные контракты, квитанции,
  классы подтверждений.
- Приватный **мост модели чата** позволяет MAGE и CARL вызывать модель того
  чата, который вызвал инструмент. Ключ провайдера не покидает харнесс. Если
  задана своя модель для цепочек (*линия разработки*), они вызывают её.
- **Политика подтверждений** стоит перед инструментами: платная работа
  спрашивает один раз, бесплатные действия проходят. См.
  [Подтверждения](/ru/care/app/confirmations/).
- *Линия разработки.* **Шлюз IdeaL** показывает собственный веб-интерфейс
  IdeaL в панели IdeaL. Он слушает только `127.0.0.1`, пускает только окно
  приложения (токен на один запуск меняется на cookie), отказывает чужим
  источникам и сам подставляет сохранённый ключ IdeaL. Поэтому ключ вводится
  один раз на странице входа IdeaL и до самой страницы не доходит.
- *Линия разработки.* **Вложения** записываются в папку проекта сессии, в
  `.maestro/attachments/`. Чтение документов достаёт из них текст для
  агента.

CLI и TUI используют тот же код предметной области, но без харнесса. Они
вызывают MAGE и CARL с настройками генератора `CARE_MAGE__*` вместо модели
чата.

## Путь данных: генерация → запуск → сохранение → эволюция

1. **План.** Вы описываете задачу. Агент изучает запрос, вложения и Память,
   спрашивает недостающее (или перечисляет допущения) и строит план со
   стратегией (повторно использовать сохранённую цепочку, написать новую
   самому, сгенерировать через MAGE, взять артефакт из этой сессии).
2. **Сборка.** По умолчанию агент чата пишет цепочку по руководству Maestro,
   проверяет, подготавливает и прогоняет её, исправляя до трёх раз. Если
   автор — MAGE, он строит цепочку на модели для цепочек. При подключённой
   памяти MAGE сначала получает выборку похожих цепочек только для чтения
   (из каталога IdeaL, если память цепочек — IdeaL). В обоих случаях
   результат — артефакт цепочки, закреплённый по SHA-256, с карточкой
   структуры и сводкой готовности.
3. **Запуск.** CARL выполняет именно этот артефакт с вашими входными
   данными, проверенными по входному контракту цепочки. Шаги вызывают модель
   для цепочек (по умолчанию модель чата), инструменты, MCP-серверы или навыки (навыки в песочнице, по
   умолчанию Docker). Запуск можно ставить на паузу между шагами.
   Неудачный запуск можно исправить: Maestro предлагает новую цепочку и сам
   её не запускает.
4. **Сохранение.** Цепочка пишется в Memory новой версией и появляется в
   «Моих агентах».
5. **Данные.** Набор данных берётся из файла CSV/TSV/XLSX в папке проекта,
   из примеров в чате или из студии наборов данных. Студия создаёт примеры,
   проверяет их и хранит версии набора с поисковой частью и скрытой закрытой
   частью. См. [Наборы данных](/ru/care/autobench/overview/).
6. **Эволюция.** Maestro отправляет исходную цепочку и поисковую часть
   набора на платформу эволюции. Если IdeaL включён, прогон несёт
   пространство и постоянный ключ задачи. Перед каждой мутацией платформа
   берёт подборку идей из IdeaL и возвращает проверенный результат.
   Кандидатов оценивает точная метрика или LLM-судья, по одной цели или по
   нескольким (фронт Парето). Статус, лучший результат, фронт и страница
   прогона в IdeaL возвращаются в приложение. См.
   [Эволюция](/ru/care/workflows/evolution/).
7. **Обучение.** IdeaL обновляет рейтинги идей по результатам. Следующая
   генерация и следующая эволюция той же задачи начинаются с этим опытом.

Лучшая цепочка завершённой эволюции подготавливается в сессии как артефакт.
В Memory она **не** пишется автоматически. Сохраните её явно.

## Где хранится состояние

| Состояние | Где | Переживает перезапуск |
| --- | --- | --- |
| Цепочки, карточки памяти, инструменты, навыки | GigaEvo Memory | Да |
| Идеи, рейтинги идей, графы прогонов эволюции | IdeaL (сервер Memory) | Да |
| Эксперименты эволюции | Платформа эволюции | Да |
| Наборы данных для эволюции | Локальный SQLite (`CARE_BENCHMARK_FACTORY_DB`) | Да |
| Прикреплённые файлы | Папка проекта сессии, `.maestro/attachments/` | Да |
| Сессии и история чата | Каталог данных харнесса | Да |
| Настройки и ключи Maestro | `~/.config/care/config.toml` и `.env` приложения (ключи там по умолчанию, `CARE_SECRET_STORE=file`) | Да |
| Ключи модели чата | Собственный файл учётных данных харнесса, только для владельца | Да |
| Фоновые задачи, список Активности в процессе, пауза цепочки, владение запуском | Процесс приложения | Нет |

## Мягкая деградация

Maestro импортирует MAGE, CARL и клиент платформы лениво, внутри функций,
которым они нужны. Отсутствующая необязательная часть даёт понятное
сообщение, а не падение при старте. Без Memory приложение по-прежнему
генерирует и запускает цепочки, но сохранение и «Мои агенты» недоступны. Без
URL платформы недоступна эволюция.
