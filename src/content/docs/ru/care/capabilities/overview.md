Цепочки выходят за пределы модели через **инструменты**, **MCP-серверы** и
**навыки**. В приложении инструменты и навыки с проверками создаёт
[мастерская](/ru/care/workflows/workshop/). В TUI и CLI всё установленное
показывает **каталог** (`Ctrl+K` в TUI,
[`maestro catalog`](/ru/care/cli/discovery/)).

## Инструменты

Инструменты — функции на Python, которые вызывают шаги-инструменты цепочки.

- **Встроенные** (включены по умолчанию, `CARE_TOOLS__ENABLE_BUILTINS`):
  `web_search`, `fetch_url`, `http_request`, `calculator`, `current_datetime`
  и `run_python`, если выполнение кода включено. `web_search` использует
  настроенного провайдера, запасной вариант — DuckDuckGo без ключа.
- **Свои инструменты**: функции с `@carl_tool` в `~/.config/care/tools`
  (`CARE_TOOLS__PATH`).
- **Инструменты мастерской**: созданы в приложении, проверены в песочнице
  Docker, сохранены в память.
- **Синтез инструментов**: если цепочка вызывает незарегистрированный
  инструмент, Maestro может написать его, один раз проверить в песочнице и
  зарегистрировать (`CARE_TOOLS__AUTO_SYNTHESIZE_TOOLS`, нужно выполнение
  кода).
- **Маршрутизация живых данных**: перед запуском цепочки только из шагов с
  моделью шаги, которым нужны живые данные (дата, погода, цены), могут быть
  переписаны в вызовы инструментов (`CARE_TOOLS__ROUTE_LIVE_DATA_TO_TOOLS`).

Как цепочки вызывают инструменты: [шаги-инструменты CARL](/ru/carl/steps/tool/).

## Решатели STARM

Алгоритмические подзадачи (судоку, лабиринты, арифметические головоломки,
«Жизнь», сетки ARC-AGI) можно отдавать небольшим обученным моделям-решателям
вместо LLM. Каждая задача — встроенный инструмент, который появляется,
только если настроен его сервер. См. [Решатели STARM](/ru/care/solvers/starm/).

## MCP-серверы

Шаг цепочки может вызвать MCP-сервер. Пример `weather` показывает настройку
(`mcp_servers.toml` и шаг `mcp`). См. [MCP в CARL](/ru/carl/mcp/overview/).

## Навыки

[AgentSkills](https://agentskills.io) — переносимые папки с `SKILL.md` и
необязательными скриптами. Каталог находит установленные навыки, а цепочки
запускают их шагами-навыками. Модель (URI, режимы выполнения, резолверы)
описана в [CARL → AgentSkills](/ru/carl/skills/overview/).

## Песочница

Скрипты навыков и сгенерированный код выполняются в песочнице. Бэкенд
выбирает `CARE_SANDBOX__KIND`:

| Бэкенд | Замечания |
| --- | --- |
| `docker` | **По умолчанию.** Нужны extra `docker` и работающий демон Docker. |
| `e2b` | Облачная микро-VM. Нужны extra `e2b` и ключ E2B. |
| `firejail` | Только Linux. |
| `local` | Обычный подпроцесс, только для внутренних тестов. Небезопасно. |

Общие правила:

- **Сеть**: `none`, `skill_declared` (по умолчанию: только домены, которые
  объявил навык) или `open`.
- **Доверие**: навыки закрепляются по SHA-256. Изменённый навык отклоняется
  до запуска любого процесса. В TUI доверие проверяют и отзывают на экране
  **Sandbox Trust** ([`/sandbox`](/ru/care/slash-commands/overview/)).
- **Лимиты**: CPU (`2.0`), память (`1g`), число процессов (`256`).
- **Проверка вывода**: файлы, созданные навыком, проверяются (биты
  исполнения, бинарники, shebang, сетевые токены, выход симлинков за
  пределы, слишком большой или пустой вывод).

Мастерская и `run_python` всегда используют песочницу Docker.

## Подмешивание контекста

Генерация может учитывать постоянный контекст (`CARE_CONTEXT__*`):

- **`CARE.md`**: глобальный файл (`~/.config/care/CARE.md`) и проектный
  `./CARE.md`, как постоянное вводное описание.
- **Долговременная память**: хранилище долговременной памяти CARL, которое
  подмешивается в промпты и обновляется после реплики.

## Телеметрия

Включите приёмник событий (Langfuse) через `CARE_TELEMETRY__*`, чтобы
трассировать генерацию и запуск. По умолчанию выключено.
