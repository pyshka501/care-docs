## Из версии набора

На вкладке **Версии** кнопка **Использовать для эволюции**:

1. готовит как артефакт сессии **только поисковую часть** версии;
2. подбирает подходящий оценщик (см.
   [Проверка ответов](/ru/care/autobench/checks/#как-проверка-становится-оценщиком-эволюции));
3. вставляет готовый запрос в поле ввода чата. Отправляете его вы.

Дальше агент строит план эволюции с оценкой токенов и после одного
подтверждения запускает эволюцию. Остальное как в обычной
[эволюции](/ru/care/workflows/evolution/).

Набор можно назвать и словами, например *«проэволюционируй цепочку про чек
на последнем наборе»*. Агент найдёт его через `maestro_find_artifacts` и
передаст короткую ссылку `dataset:<id>`, а не будет переписывать длинные id
артефактов.

### Когда кнопки нет

| Версия | Что написано вместо кнопки |
| --- | --- |
| Задачи с инструментами (`stateful_env`) | эволюция появится вместе с оценщиком по состоянию среды |
| Вход с файлами | эволюция на файлах пока недоступна |
| Меньше 2 примеров в поиске или проверка, которую эволюция не воспроизводит | для эволюции не подходит |

## Закрытая часть

- Закрытая часть выбирается **по семействам**, а не по отдельным примерам,
  поэтому эволюция не видит вариаций спрятанного шаблона. Нужно хотя бы 3
  семейства, в поиске всегда остаётся не меньше 2, сначала прячутся сложные
  семейства, пока по весам не наберётся заданная доля (по умолчанию 25%).
- При новой версии спецификации закрытые семейства остаются закрытыми.
- Отдельные примеры можно переносить между частями во вкладке **Примеры**, а
  целые семейства для одной версии во вкладке **Пропорции**.
- Эталоны и файлы закрытой части инструменты агента не возвращают, на экране
  они скрыты. Строки лежат в локальном хранилище.

:::caution[Финальная проверка ручная]
В этой сборке ничто не оценивает победителя эволюции и исходную цепочку на
закрытой части. План эволюции помечает это сравнение как ручной шаг, и
победитель сам в память не попадает. Лучший фитнес на обучении считайте
подсказкой, а не доказательством.
:::

## Сколько строк реально оценивает эволюция

Раннер платформы эволюции ставит для экспериментов с цепочками
`CARL__MAX_TRAIN_SAMPLES=2` и `CARL__MAX_VAL_SAMPLES=1`, а время на цепочку
ограничивает 15 секундами. Значит, каждая оценка смотрит **2 строки обучения
и 1 строку валидации**, каким бы большим ни был поиск. Оценка стоимости
Maestro для оценщика с критерием исходит из тех же 3 строк на оценку.

Это по чтению кода платформы. В более раннем живом прогоне (2026-09-28)
платформа валидировала на 2 строках из 11. Баллы на маленькой выборке шумные,
читайте их вместе с размером набора.

## Импорт своего файла

Если примеры уже есть в таблице, агент может импортировать её вместо
генерации. Положите файл в папку проекта и попросите, например
*«импортируй примеры из @data/cases.xlsx, колонка с ответом называется «Ответ»»*.
Агент вызовет `maestro_dataset_import`.

| Параметр | По умолчанию | Смысл |
| --- | --- | --- |
| `path` | — | Относительный путь внутри папки проекта. Без `..` и симлинков. |
| `sheet` | первый лист | Имя листа XLSX. |
| `columns` | все | Какие колонки оставить, как они названы в файле. |
| `rename` | — | `{"Колонка в файле": "new_name"}`. |
| `target_column` | `expected` | Колонка с эталоном после переименования (латиницей). |
| `header_row` | 1 | Строка с заголовками. |
| `max_rows` | — | Ограничение строк (2–1000). |
| `delimiter` | определяется сам | `,` `;` табуляция или `\|` для CSV/TSV. |

Ограничения: `.csv`, `.tsv`, `.xlsx`, `.xlsm`; до 20 МБ; 2–1000 строк; до 64
колонок; ячейки длиннее 8 192 символов обрезаются. CSV читается как UTF-8, при
ошибке как Windows-1251. Строки с пустым эталоном пропускаются.

Что получится:

- Модель не вызывается, подтверждение не спрашивается.
- Инструмент возвращает число строк и колонок, имена колонок и
  предупреждения, но не значения ячеек: они сразу уходят в приватный
  артефакт.
- Ссылка `dataset:import-…`, которую можно назвать для эволюции.
- Закрытой части и проверок нет: оценщик по умолчанию считает похожесть
  (ROUGE-L) и показывается в плане для проверки. Если важны точные ответы,
  попросите другой оценщик.

Импортированные наборы не являются процессами автобенчмарка: в **Наборах
данных** их нет, править и пересобирать их там нельзя. Ссылку помнит только
работающий процесс сессии (последние 16 импортов).
