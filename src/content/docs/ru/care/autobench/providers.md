Процесс использует одного провайдера на всё: спецификацию, примеры, слепое
решение и судью. Его выбирают в мастере (**Провайдер**) или передаёт агент.
Если не выбрать, Maestro берёт Codex, когда он доступен, иначе модель чата.

| | Codex | Модель чата |
| --- | --- | --- |
| Что это | Локальный Codex CLI с входом в ваш аккаунт ChatGPT | Модель, через которую идёт генерация цепочек |
| Кто платит | Лимиты вашей подписки ChatGPT | Ключ модели чата |
| Вывод | Ограничен JSON-схемой (`--output-schema`) | Просит `json_schema`, при отказе `json_object` |
| Файлы на входе (картинки, PDF, DOCX, XLSX, CSV, аудио) | Да | Нет |
| Параллельных пакетов | до 3 | до 2 |
| Бюджет по умолчанию, если агент его не указал | 1 000 000 токенов | 200 000 токенов |
| Счёт токенов | Оценка, которую печатает CLI | Данные API |

Сам мастер по умолчанию ставит 1 000 000 токенов для обоих.

## Codex

### Что ищет Maestro

Codex **доступен**, когда выполнены оба условия:

1. **Найден бинарь Codex**, в таком порядке:
   - `MAESTRO_CODEX_BIN`, если задана (должна указывать на существующий файл);
   - `codex` в `PATH`;
   - `/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex`
   - `/Applications/Codex.app/Contents/Resources/codex`
   - `~/.local/bin/codex`
   - `/opt/homebrew/bin/codex`
   - `/usr/local/bin/codex`
2. **Codex вошёл в аккаунт**: в домашней папке Codex (`$CODEX_HOME`, по
   умолчанию `~/.codex`) есть `auth.json`. Если нет, один раз выполните
   `codex login`.

Если Codex недоступен, мастер пишет почему: «Codex CLI не найден…» (нет
бинаря) или «Codex не вошёл в аккаунт…».

Список моделей берётся из `models_cache.json` в домашней папке Codex (до 24
моделей, review-модели исключены). По умолчанию `gpt-6-luna`, если она в
списке или список пуст; иначе первая модель из списка.

### Как Maestro его вызывает

Один процесс `codex exec` на вызов модели, с флагами:

- `--ignore-user-config`: ваши настройки Codex, хуки уведомлений, плагины и
  модель по умолчанию не применяются;
- `--ephemeral`: без файлов сессии;
- `--ignore-rules` и `--skip-git-repo-check`;
- песочница только для чтения в пустой временной папке или
  `workspace-write`, ограниченная рабочей папкой пакета, когда нужно создать
  файлы; судья и слепой решатель в процессе с файлами читают файлы процесса,
  но ничего не пишут;
- `-c model_reasoning_effort=…`, если выбрано усилие рассуждения.

Одновременно работает не больше 3 процессов Codex на все генерации
(`MAESTRO_CODEX_CONCURRENCY`, по умолчанию 3). Токены берутся из строки
«tokens used» в выводе CLI и являются оценкой; на экране процесса стоит
пометка «оценка Codex».

## Модель чата

«Модель чата» здесь та, что генерирует цепочки: по умолчанию модель чата
сессии («модель текущего чата») или модель цепочек из настроек MAESTRO, если
генерация цепочек переключена на свою модель («модель из настроек: …»). Если
при старте подключения к модели нет, процесс ждёт в статусе **Требует
возобновления** с причиной «модель недоступна»; продолжите, когда модель
заработает.

С моделью чата один запуск, продолжение или догенерация получает аренду
модели не больше чем на 600 вызовов и 6 часов.

## Переменные окружения

| Переменная | Что делает |
| --- | --- |
| `MAESTRO_CODEX_BIN` | Путь к бинарю Codex. |
| `CODEX_HOME` | Домашняя папка Codex с `auth.json` и `models_cache.json` (по умолчанию `~/.codex`). |
| `MAESTRO_CODEX_CONCURRENCY` | Сколько процессов Codex может идти параллельно (по умолчанию 3). |
| `MAESTRO_GENERATOR_PYTHON` | Python для программ-генераторов. По умолчанию текущий интерпретатор, в собранном приложении `/usr/bin/python3`. |
| `MAESTRO_GENERATOR_SANDBOX` | `0` запускает генераторы без `sandbox-exec`. Не выключайте. |
| `CARE_BENCHMARK_FACTORY_DB` | Путь к хранилищу автобенчмарка (см. [Инструменты агента](/ru/care/autobench/tools/#хранилище)). |
