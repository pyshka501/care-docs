## Где запустить

- **Наборы данных** в панели [Библиотеки](/ru/care/app/library/) →
  **Новый набор**. Нужна открытая сессия. Мастер подставит последнюю цепочку
  из чата этой сессии.
- Сохранённая цепочка в списке Библиотеки или карточка цепочки в чате →
  **Сгенерировать данные для эволюции**. Мастер откроется на месте, с этой
  цепочкой.
- Страница цепочки в Библиотеке → **Данные для эволюции**. Откроется новая
  сессия с готовым запросом агенту, отправляете его вы.
- Попросите агента, например *«собери данные для эволюции цепочки про сумму
  чека, 40 примеров»*. См. [Инструменты агента](/ru/care/autobench/tools/).

Запущенные процессы видны и в [Активности](/ru/care/app/activity/), оттуда
они открываются в **Наборах данных**.

## Мастер

Три шага: **Задача**, **Формат и проверка**, **Модель и объём**.

### 1. Задача

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| Задача агента | из цепочки | Что делает агент и что получает на вход. Обязательное. |
| Как создавать примеры | Модель пишет примеры | **Модель пишет примеры**: пакеты со структурированным ответом, эталон подтверждается слепым решением и судьёй. **Модель пишет генератор**: для данных, которые можно вычислить (уравнения, даты, расчёты); см. [Программа-генератор](#программа-генератор). |
| Вход агента | Ответ текстом | **Ответ текстом**: агент получает вход и отвечает. **Задачи с инструментами**: агент действует в среде с данными, проверяется итоговое состояние. См. [Задачи с инструментами](#задачи-с-инструментами). |
| Модальность входа | Текст | Текст, Изображение, PDF, Документ Word, Таблица Excel, CSV, Аудио. Поле есть только для текстового ответа, который пишет модель. Любой файл переключает провайдера на Codex. См. [Файлы на входе](#файлы-на-входе). |

Если цепочка приложена, поля примера берутся из её ссылок `input.<имя>`.
Без цепочки поле одно: `text`.

### 2. Формат и проверка

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| Формат входа | пусто | Необязательно. Как выглядит вход, например «текст чека с позициями, скидками и итогом; иногда без итога». |
| Формат ответа | пусто | Необязательно. Например «только число с двумя знаками после запятой, без валюты». Эталоны пишутся в этом формате. |
| Особенности | пусто | Необязательно. Например «больше неоднозначных формулировок, 20% заданий на английском». |
| Метод проверки | Авто | Как решается, верен ли ответ. См. [Проверка ответов](/ru/care/autobench/checks/). |
| Шаблон / Поле JSON / Допуск / Метки | — | Дополнительное поле для **Регулярного выражения** (обязательно), **Поля JSON**, **Числа** (допуск, по умолчанию 0) и **Метки из списка** (через запятую; если пусто, метки придумает модель). |
| Описание правильного ответа | пусто | Своими словами, что считать верным. У **Судьи-модели** это поле называется **Критерий для судьи**: его читает судья при проверке примеров, его же получает оценщик эволюции. |

### 3. Модель и объём

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| Провайдер | Codex, если доступен, иначе модель чата | **Codex**: через ваш вход в ChatGPT, структурированный вывод, умеет создавать файлы. **Модель чата**: текущая модель чата, файлы не создаёт. См. [Провайдеры](/ru/care/autobench/providers/). |
| Модель Codex | `gpt-6-luna`, если она есть в списке вашего Codex CLI, иначе первая из списка | Только для Codex. |
| Усилие рассуждения | среднее | низкое (быстрее), среднее, высокое (точнее). Только для Codex. |
| Когда остановиться | Набрать нужное число | См. [Остановка и бюджет](#остановка-и-бюджет). |
| Примеров | 24 | 4–500. В двух других режимах остановки это размер первого раунда. |
| Лимит вызовов модели | 60 | 1–5000. Только для режима «Пока есть запросы». |
| Сложность | сбалансированно | проще, сбалансированно, сложнее: доли лёгких, средних и сложных 50/40/10, 20/50/30 или 5/35/60 %. |
| Закрытая часть, % | 25 | 0–50. В закрытую часть уходят целые семейства, а не отдельные примеры. |
| Примеров за вызов | 10 | 1–25. Размер пакета. Только когда примеры пишет модель. |
| Бюджет, токенов | 1 000 000 | От 5 000; сервер принимает до 5 000 000. |

**Запустить генерацию** стартует процесс. Кнопка неактивна, если выбран
Codex, а он недоступен, или выбран файл без Codex; причина написана под
формой.

Сервер тоже отказывает в некоторых сочетаниях: файлы без Codex, файлы в
задачах с инструментами, генератор для задач с инструментами или с файлами,
режим «Пока есть запросы» без лимита.

## Остановка и бюджет

| Режим | Когда стоп |
| --- | --- |
| **Набрать нужное число** | Принятых примеров стало столько, сколько указано в **Примеров**. Отклонённые добираются до 3 дополнительных раундов. |
| **Пока не кончится бюджет** | Израсходован бюджет токенов. Каждый раунд добавляет по пакету в каждое семейство, где ещё что-то принимается. |
| **Пока есть запросы** | Исчерпан **Лимит вызовов модели**. Удобно при лимитах подписки. |

В любом режиме процесс заканчивается, если три раунда добора подряд не дали
ни одного принятого примера. Семейство, которое на полном пакете не дало ни
одного принятого, больше не добирается.

Что важно для расхода (по коду):

- Пакеты идут параллельно: до 3 сразу с Codex, до 2 с моделью чата.
- Бюджет проверяется **между** пакетами. Начатые пакеты доделываются, так что
  итог может немного выйти за бюджет.
- Раунды добора планируются по оценке 30 000 токенов на пакет для Codex и
  8 000 для модели чата.
- Токены Codex берутся из вывода Codex CLI и являются оценкой; на экране
  стоит пометка «оценка Codex». Codex тратит лимиты вашей подписки ChatGPT,
  модель чата тратит её ключ.
- С моделью чата один запуск (продолжение, догенерация) получает аренду
  модели не больше чем на 600 вызовов и 6 часов.

Любой завершённый или остановленный процесс сохраняет версию набора из
принятого, по какой бы причине он ни закончился. Если принятых нет, версия не
создаётся.

## Что платно и где спросят подтверждение

| Действие | Вызовы модели | Подтверждение |
| --- | --- | --- |
| **Запустить генерацию** в мастере | да, в пределах бюджета | нет: нажатие кнопки и есть согласие |
| Агент запускает генерацию | да | одно окно приложения |
| Пауза, Остановить и сохранить, Повторить неудачные | новой работы нет | нет |
| Продолжить | продолжается платная работа в одобренном бюджете | нет |
| Инструкция по ходу | один вызов на спецификацию, в бюджете | нет |
| Правка, принятие, исключение, перенос, добавление примера; превью и сохранение пропорций | нет | нет |
| Догенерация недостающих на вкладке **Пропорции** | да, платно (для генератора бесплатно) | с экрана нет; окно, если просит агент |
| Вкладка «Генератор»: проверка, сохранение кода, генерация | нет, всё локально | с экрана нет |
| Вкладка «Генератор»: попросить модель изменить код | один вызов | с экрана нет |

Если у сессии пресет одобрения «никогда не спрашивать», вызовы агента
проходят без окон. См. [Подтверждения](/ru/care/app/confirmations/).

## По ходу генерации

Процесс открывается в **Наборах данных** с вкладками **Обзор**, **Примеры**,
**Пропорции**, **Генератор** (только для программы-генератора), **Версии** и
**Журнал**.

На **Обзоре** видны стадии (**Спецификация**, **Генератор**, **Генерация**,
**Проверка**, **Сохранение**), полоса прогресса к условию остановки и
счётчики: создано, принято, отклонено, без проверки, исключено, устарело,
токены, вызовы модели, время.

Управление:

- **Пауза**: новые пакеты не выдаются, текущие доделываются. **Продолжить**
  идёт с сохранённой точки и переиспользует готовое.
- **Повторить неудачные**: ставит упавшие пакеты в очередь заново.
- **Остановить и сохранить**: процесс заканчивается насовсем, проверенные
  примеры сохраняются версией.
- **Инструкция по ходу** → **Отправить**, например *«Добавь больше случаев с
  неоднозначными именами»*. Применяется в ближайшей безопасной точке и даёт
  новую версию спецификации. Примеры, которые ей больше не соответствуют,
  становятся **устаревшими**. Неясная инструкция переводит процесс в «Ждёт
  уточнения».

В раскрывающемся блоке **Спецификация vN** видны цель, критерий успеха и
семейства со сложностью и частью (поиск или закрытая).

Процессы долговечны. Если приложение перезапустилось во время генерации,
процесс получит статус **Требует возобновления** и после **Продолжить**
пойдёт с сохранённого места. Доступ к модели хранится только в памяти
процесса, поэтому для продолжения нужно рабочее подключение к модели в
текущей сессии.

## Программа-генератор

В режиме **Модель пишет генератор** модель пишет один модуль Python с
функцией `generate(rng, family, difficulty)`, которая возвращает вход, эталон
и короткое обоснование. Дальше:

1. Программа запускается на 12 пробных примерах; годных должно быть хотя бы
   8, иначе модель получает ошибки и пробует снова (до 3 попыток).
2. Программа генерирует примеры. Эталоны верны по построению.
3. Аудит: до 8 принятых примеров модель решает вслепую. Если проверено хотя
   бы 4 и совпало меньше половины, процесс встаёт на паузу с причиной «аудит
   генератора не пройден». Посмотрите код.

Программа использует только стандартную библиотеку, должна работать на
Python 3.9 и запускается локально под `sandbox-exec` macOS: без сети, запись
только в свою временную папку, без чтения папок с ключами (`~/.codex`,
`~/.ssh`, `~/.aws`, `~/.config`, связки ключей, Документы, Рабочий стол,
Загрузки), 60 секунд на запуск, не больше 2 000 примеров за запуск.
Генерация новых примеров готовой программой не вызывает модель.

Генератор работает только для текстового входа и текстового ответа.

## Файлы на входе

С файловой модальностью Codex сначала пишет данные и эталон, потом создаёт
файл строго по ним в рабочей папке. Файл принимается, только если он внутри
этой папки, у него правильное расширение и сигнатура (PNG/JPG/WebP; PDF;
DOCX; XLSX; CSV в UTF-8; WAV/AIFF/M4A/MP3) и он не больше 20 МБ. Пакет без
годного файла считается неудачной попыткой и повторяется. Во входе примера
появляется поле `file` с путём.

Принятые файлы лежат рядом с хранилищем в `assets/<run_id>/`. На вкладке
**Примеры** видно превью картинок, аудио и PDF; файлы закрытой части не
показываются.

Наборы с файлами можно смотреть, править и экспортировать, но **нельзя
отдать в эволюцию**: цепочки принимают только текст.

## Задачи с инструментами

В режиме **Задачи с инструментами** модель сначала проектирует декларативную
среду: таблицы с записями и инструменты (поиск, изменение, добавление,
удаление) с предусловиями. Если у цепочки есть шаги-инструменты, их
интерфейсы переиспользуются под теми же именами. У каждого задания одно поле
входа, `instruction` (просьба пользователя); в скрытом эталоне ожидаемые
вызовы инструментов и проверки итогового состояния.

Задание принимается, если эталонные вызовы проходят в чистой среде, заведомо
неверное поведение не проходит, а независимое слепое решение проходит ту же
проверку. В эволюцию такие наборы пока не отдать: оценщик эволюции проверяет
только текст ответа.
