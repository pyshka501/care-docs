Основной цикл «сгенерировать → запустить», а также экспорт цепочек на диск и
повтор прошлых запусков. Генерация и исполнение вызывают модель. Это занимает от
нескольких секунд до нескольких минут и на платном endpoint стоит денег.

## `maestro generate "<task>"`

Генерирует цепочку по описанию задачи в свободной форме.

```bash
maestro generate "weather report for SF" --save weather --output /abs/weather.json
maestro generate "summarise a PDF report" --mode deep --json
```

| Флаг | Назначение |
| --- | --- |
| `--mode fast\|deep` | Режим генерации. Без флага действует режим генератора по умолчанию. |
| `--save NAME` | Сохранить цепочку в Memory под именем `NAME` (новая сущность). Без флага ничего не сохраняется. |
| `--output PATH` | Записать цепочку в файл; формат по расширению (`.json` / `.py`). |
| `--output-format json\|python` | Задать формат явно. |
| `--json` | Напечатать цепочку как JSON вместо строки-сводки. |

Если генерация упала из-за ключа или истёкшего токена, CLI вместо трейсбека
печатает одну подсказку: `maestro init` (заново записать ключи) и `maestro doctor`
(проверить endpoint).

:::note[Один файл или пакет?]
Для одного файла используйте `generate --output PATH` или, для сохранённой цепочки,
`run --export PATH`. Обе команды пишут `.json` или запускаемый `.py`. Чтобы
передать несколько цепочек вместе с их AgentSkills одним tarball, используйте
[`maestro export`](/ru/care/cli/export/).
:::

## `maestro run <chain_id>`

Получает сохранённую цепочку из Memory и выполняет preflight. Preflight сообщает,
какие инструменты, MCP-серверы и навыки нужны цепочке и каких не хватает. Модель
при этом не вызывается. Чтобы запустить цепочку, добавьте `--execute`.

```bash
maestro run weather                                   # только preflight
maestro run weather --execute --input city=Paris --save-result paris-run
maestro run report-digest --execute --file /abs/report.pdf
maestro run weather --export /abs/chain.py            # экспорт без запуска
```

| Флаг | Назначение |
| --- | --- |
| `--channel NAME` | Канал версии (по умолчанию `latest`). |
| `--execute` | Запустить цепочку после preflight. Нужны extra `carl` и ключ модели. |
| `--task TEXT` | Заменить `outer_context`. Без флага берётся сохранённое описание задачи. |
| `--input KEY=VALUE` | Добавить пару в `context.memory['input']` (можно повторять). |
| `--file PATH` | Приложить содержимое файла под его именем (можно повторять). |
| `--classify-files heuristic\|model` | Как решать, какие шаги-навыки читают входной файл: `heuristic` (по ключевым словам, по умолчанию, детерминированно) или `model` (спросить модель, нужен ключ). |
| `--save-result NAME` | Сохранить сводку запуска как `memory_card` с тегами `run-record` и `chain:<id>`. Только вместе с `--execute`. |
| `--export PATH` | Заодно записать цепочку в файл (`.json` / `.py`). |
| `--export-format json\|python` | Задать формат экспорта. |
| `--json` | Напечатать результат preflight как JSON. |
| `--log PATH` | Дописывать структурированный отладочный лог запуска (вызов, получение, preflight, экспорт, исполнение, сохранение). |
| `--log-level debug\|info` | `info` (по умолчанию) пишет основные этапы; `debug` добавляет трейсбеки и саму цепочку. |

:::note[Куда попадают входы]
Значения `--input` и `--file` попадают в `context.memory['input']`. Шаг-инструмент
или MCP-шаг читает их ссылкой `$memory.input.<key>` в `input_mapping` /
`argument_mapping`. LLM-шаги видят те же значения как JSON-блок, добавленный к
тексту задачи с пометкой «недоверенные данные». Ссылка `$outer_context.<field>` их
**не** находит: при наличии входов внешний контекст — это текст задачи, а не
JSON-объект.
:::

## `maestro replay <source>`

Проходит по сохранённому JSON `ReasoningResult` / `RunRecord` прошлого запуска.
`-` читает из stdin.

```bash
maestro replay /abs/run.json            # весь сеанс, блок на шаг
maestro replay /abs/run.json --step 2   # только шаг 2 (с нуля)
cat run.json | maestro replay -
```

| Флаг | Назначение |
| --- | --- |
| `--step N` | Показать только шаг N (нумерация с нуля). |
| `--json` | Структурированные данные (метаданные цепочки и все шаги). |

## Решатели в сгенерированных цепочках

Если настроены серверы STARM, генератор может поставить в цепочку `solve_sudoku`,
`solve_maze` и другие инструменты-решатели, а `run --execute` их вызовет. В CLI
ошибка решателя возвращается текстом для следующего шага. Ответ, не прошедший
локальную проверку, помечается `REJECTED by a local check`. См.
[Решатели STARM](/ru/care/solvers/starm/).

Актуальный список флагов: `maestro <команда> --help`.
