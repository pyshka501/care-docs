У Maestro три интерактивных интерфейса. Все читают один конфиг и одну Memory:
цепочка, сохранённая в одном, видна в остальных.

| Команда | Что открывает | Статус |
| --- | --- | --- |
| `maestro` или `maestro app` | Приложение на основе харнесса Maestro | Основной интерфейс |
| `maestro tui` | Терминальный интерфейс Textual | Поддерживается как дополнительный |
| `maestro web` | Локальный браузерный интерфейс | Инструмент разработчика, только loopback |

Консольный скрипт `maestro-app` делает то же, что `maestro app`.

## `maestro app`

Открывает приложение в нативном окне и работает, пока окно не закроют. `maestro`
без подкоманды делает то же самое. В приложении харнесс Maestro ведёт генерацию,
исполнение, эволюцию, Memory, IdeaL и решатели STARM через собственные инструменты.
Подробности в разделе «Приложение».

```bash
maestro app
maestro app --width 1440 --height 900
maestro app --debug                 # диагностика WebView
maestro app --legacy-workbench      # прежний интерфейс workbench
```

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--width N` | `1280` | Начальная ширина окна в логических пикселях. |
| `--height N` | `820` | Начальная высота окна в логических пикселях. |
| `--debug` | выкл. | Включить диагностику WebView для разработчика. |
| `--legacy-workbench` | выкл. | Запустить прежний workbench вместо харнесса. |
| `--port N` | `0` | Loopback-порт, **только** вместе с `--legacy-workbench`. Харнесс всегда берёт свой временный порт. Другое значение без `--legacy-workbench` даёт код выхода `2`. |

Минимальный размер окна 920×620. С меньшими `--width` / `--height` приложение не
запустится. Нужен extra `desktop` (в собранном приложении для macOS он уже есть).

### Флаги разработчика для харнесса

По умолчанию приложение находит харнесс, который поставляется вместе с ним, и
проверяет, что его версия совпадает с закреплённой. Три флага меняют это поведение.
Они нужны тем, кто собирает сам Maestro:

```bash
maestro app --dsh-executable /path/to/harness-binary   # взять этот исполняемый файл
maestro app --dsh-source /path/to/built-checkout       # или собранный checkout
maestro app --dsh-home /path/to/private-state-dir      # приватный каталог состояния
maestro app --allow-dsh-version-drift                  # разрешить незакреплённую версию
```

`--dsh-executable` и `--dsh-source` взаимоисключающие. С
`--allow-dsh-version-drift` совместимость не гарантируется.

Коды выхода: `0` после обычного закрытия, `2`, если приложение не загрузилось или не
стартовало, `130` по Ctrl+C.

## `maestro tui`

Открывает терминальный интерфейс Textual в текущем терминале. Флагов нет. См.
[TUI](/ru/care/tui/overview/).

```bash
maestro tui
```

## `maestro web`

Поднимает локальный браузерный интерфейс и открывает вкладку браузера. Это
инструмент разработчика, а не замена приложению. Слушает только loopback-адрес.

```bash
maestro web                          # http://127.0.0.1:8787
maestro web --port 0 --no-open       # любой свободный порт, без вкладки
```

| Флаг | По умолчанию | Назначение |
| --- | --- | --- |
| `--host` | `127.0.0.1` | Loopback-адрес: `127.0.0.1`, `localhost` или `::1`. |
| `--port` | `8787` | TCP-порт; `0` выбирает свободный. Допустимо 0–65535. |
| `--no-open` | выкл. | Поднять сервер, не открывая браузер. |

Остановка по Ctrl+C (код выхода `130`).
