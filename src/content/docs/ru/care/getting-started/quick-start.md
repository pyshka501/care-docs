Эта страница ведёт от чистой машины до первого собранного и запущенного
агента (цепочки) в приложении Maestro. Путь через CLI и TUI описан в конце.

## Что нужно

- **macOS на Apple silicon** для `Maestro.app`. Сборка только под arm64. Из
  исходников приложение запускается и в WebView других платформ, но
  проверена именно macOS.
- API-ключ провайдера модели для чата. По умолчанию это **OpenRouter**.
  Подойдут и другие провайдеры из настроек модели чата, OpenAI-совместимый
  адрес или (*линия разработки*) подписка ChatGPT Plus/Pro.
- По желанию: работающая **GigaEvo Memory** (чтобы сохранять цепочки;
  локально по умолчанию `http://localhost:8002`), **GigaEvo Platform** (для
  эволюции; локально `http://localhost:8000`) и **Docker** (песочница по
  умолчанию для навыков и для проверки инструментов в мастерской).

## 1. Установка и запуск

### Вариант A: `Maestro.app`

Откройте `Maestro.app`. Обычному запуску не нужны Python, Node.js и другие
исходники: сборка несёт свой runtime. Сборка подписана ad-hoc и не
нотаризована, поэтому macOS может попросить подтвердить первый запуск
скачанной копии.

Чтобы собрать бандл самостоятельно, следуйте `packaging/macos/README.md` в
репозитории Maestro. Нужен framework-Python для macOS (py2app не работает со
standalone-Python от uv). Из корня репозитория:

```bash
uv venv --python /opt/homebrew/bin/python3.12 .venv-py2app
uv pip install --python .venv-py2app/bin/python -e '.[macos-app,dev]'
.venv-py2app/bin/python packaging/macos/setup.py py2app
.venv-py2app/bin/python packaging/macos/verify_bundle.py
codesign --verify --deep --strict --verbose=2 dist/Maestro.app
```

Для сборки также нужны подготовленные файлы runtime харнесса и исходники
CARL. README сборки перечисляет их и объясняет, как их получить.

### Вариант B: из исходников

Нужны Python 3.12 или 3.13 и [`uv`](https://docs.astral.sh/uv/).

```bash
uv sync --extra desktop
uv run maestro            # то же, что uv run maestro app
```

Обычный `uv sync` не ставит extra `desktop`, поэтому один раз выполните
команду выше. Запуску из исходников также нужен закреплённый runtime
харнесса. Maestro ищет его в таком порядке: явный флаг или переменная
окружения, runtime внутри установленного `Maestro.app`, собранный checkout
runtime рядом с репозиторием Maestro, затем исполняемый файл в `PATH`. Если
ничего не найдено, запуск останавливается с сообщением, что установить.
Флаги для разработчиков, указывающие на runtime, есть в `maestro app
--help`, а README сборки говорит, где взять исходники runtime.

Если версия runtime отличается от закреплённой, запуск останавливается.

Приложение открывает нативное окно. В браузере ничего не открывается:
харнесс слушает только случайный порт `127.0.0.1` внутри окна. Закрытие окна
его останавливает.

## 2. Выберите папку проекта

На стартовом экране выберите папку проекта («Выберите папку проекта»).
Сессии принадлежат папке проекта, а прикреплённые в чате файлы сохраняются
в неё. Она нужна и тем кнопкам «Моих агентов», которые открывают сессию.

Собранное приложение хранит свой файл настроек `.env` в
`~/Documents/Maestro`, если вы не запустили его из терминала в другой
папке.

## 3. Настройте модель чата

При первом запуске приложение просит ключ **OpenRouter**. Для другого
провайдера откройте **Настройки → Модель чата**, добавьте его, введите
API-ключ и выберите модели для выбора модели. Чтобы работать через подписку
ChatGPT вместо ключа, войдите в **Настройки → Codex**. Ключ остаётся внутри
харнесса и не записывается в файлы конфигурации Maestro.

Для приложения это единственная нужная модель. Написание и запуск цепочек,
генерация, исправление, работа с наборами данных, черновики инструментов и
навыков и перевод идей идут на модели, выбранной в текущем чате, если в
Настройки → MAESTRO не задана своя модель для цепочек. Не вставляйте ключи в
чат.

## 4. Подключите память и эволюцию (по желанию)

Откройте **Настройки → MAESTRO**. Здесь задаются:

- **«Адрес памяти»**; **«Память цепочек»**: поиск по библиотеке или
  **IdeaL** с пространством или проектом. Ключ IdeaL вводится один раз, на
  странице входа в панели IdeaL в боковой панели;
- в блоке **«Расширенные»**: **«Только чтение»** для общего хранилища,
  адрес платформы эволюции и её модели мутаций и проверки, исследование при
  генерации и блокировка приложения;
- вверху: кто пишет цепочки, как агент уточняет задачу и какая модель
  работает с цепочками.

Остальные ключи вводятся в нативном окне для секретного ввода. По умолчанию
они хранятся в собственных файлах Maestro с доступом только для владельца, а
не в связке ключей (`CARE_SECRET_STORE`). Каждое сохранение требует
нативного подтверждения и **полного перезапуска** приложения. См.
[Настройки](/ru/care/app/settings/).

## 5. Соберите первого агента

Нажмите **«Новый агент»** и опишите задачу своими словами или выберите
карточку под полем ввода:

```text
Сделай агента, который принимает отзыв клиента и возвращает его тональность
(позитивная, нейтральная или негативная) с объяснением в одну строку.
```

Агент изучит запрос и спросит недостающее карточкой вопросов (вход, формат
ответа, критерий качества). Выберите вариант или впишите свой. Потом он
покажет короткий бриф и соберёт цепочку.

По умолчанию агент чата пишет цепочку сам и **прогоняет** её на
реалистичном входе. Тестовый прогон вызывает модель, поэтому приложение
покажет **одно окно подтверждения**. Появится карточка цепочки с графом шагов
и пометкой «Проверена запуском», когда тест прошёл. (Если в **«Кто пишет
цепочки»** стоит **MAGE**, цепочку собирает генератор, окно одно на
генерацию, а цепочка помечена «Не проверена запуском».)

Затем попросите запустить на ваших данных:

```text
Запусти на: «Доставка опоздала, но поддержка всё решила за десять минут.»
```

Запуск спросит подтверждение ещё раз. Карточка результата показывает превью
вывода каждого шага. Пока запуск идёт, его можно поставить на паузу,
продолжить или остановить с карточки.

Если память настроена, попросите «сохрани этого агента». Сохранение
бесплатное и проходит без окна. После этого агент появится в **«Моих
агентах»**.

Чтобы платная работа в одной сессии шла без окон, выберите для неё режим
доступа **«Полный доступ»**. См. [Подтверждения](/ru/care/app/confirmations/).

## Быстрый старт: CLI и TUI

CLI и Textual TUI **не** используют модель чата приложения. Они работают с
настройками генератора `CARE_MAGE__*` (URL провайдера, модель, ключ).

```bash
uv sync
uv run maestro init         # пишет ./.env с настройками CARE_MAGE__*
uv run maestro doctor       # что настроено, живые проверки
uv run maestro tui          # Textual TUI
```

`maestro init` записывает API-ключ в `.env` **открытым текстом**.
Неинтерактивный вариант:

```bash
uv run maestro init --non-interactive \
  --api-key "$OPENROUTER_API_KEY" \
  --base-url https://openrouter.ai/api/v1 \
  --model qwen/qwen3-coder
```

Ключи из `~/.config/care/config.toml` можно перенести в хранилище ОС командой
`uv run maestro migrate-secrets`.

В TUI введите задачу и нажмите <kbd>Enter</kbd>. В режиме **Interactive** (по
умолчанию) Maestro генерирует цепочку, спрашивает перед запуском и
показывает ответ. `/tour` проводит короткую экскурсию. Режимы описаны в
[Interactive и Production](/ru/care/workflows/modes/).

Разовый вызов из оболочки:

```bash
uv run maestro generate "Classify review sentiment" --save sentiment
uv run maestro run <chain_id> --execute --task "Delivery was late, support was great"
```

См. [справочник CLI](/ru/care/cli/overview/).
