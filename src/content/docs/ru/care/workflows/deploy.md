`/deploy` (команда TUI) отправляет сохранённую цепочку в **хаб агентов**. Это
лёгкий локальный процесс, который обслуживает каждую развёрнутую цепочку как
HTTP-агента по адресу `/agents/<name>` со своим Swagger UI на
`/agents/<name>/docs`.

## Установка

Хаб поставляется отдельным пакетом, чтобы базовая установка оставалась
лёгкой:

```bash
pip install "maestro-care[deploy]"
```

Это добавит CLI `carl-agent-hub` в PATH (он есть и в extra `[full]`). TUI сам
запускает хаб при первом `/deploy`, поэтому вручную его запускать почти не
нужно.

## Развернуть цепочку

В TUI, при настроенной Memory:

```text
/deploy <ref> [--channel <ch>] [--name <agent>]
```

- **`<ref>`**: id сущности цепочки или поисковый запрос по имени (может
  содержать пробелы).
- **`--channel`**: какой канал развернуть. По умолчанию **`stable`**: в
  продакшн уходит выпущенная версия, а не текущая разработка.
- **`--name`**: имя агента в хабе (по умолчанию берётся из цепочки).

Что происходит:

1. **Поиск** цепочки в запрошенном канале (с откатом на `latest`).
2. **Проверка перед развёртыванием** на стороне клиента: цепочка
   загружается, использует только безопасные для шаблона инструменты и
   проходит lint MAGE. При ошибке выводится список проблем, и **ничего не
   развёртывается**.
3. **Запуск хаба**: если хаб не работает и `autostart` включён, TUI
   запускает его и ждёт `/healthz`.
4. **Развёртывание**: `POST /deployments`, хаб подключает агента.
5. Вы получаете **URL агента**, ссылку на его **Swagger** и строку о
   готовности.

## Что получается

Каждое развёртывание — HTTP-агент в хабе:

- **Endpoint агента**: `…/agents/<name>`
- **Swagger UI**: `…/agents/<name>/docs`

Один хаб держит много цепочек и сохраняет их между перезапусками (в своём
`state_file`), поэтому развёрнутые агенты переживают перезапуск хаба.

## Настройка хаба

Раздел `[hub]` (префикс окружения `CARE_HUB__`):

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `base_url` | `http://127.0.0.1:8080` | Управляющий API хаба, к которому обращается клиент. |
| `port` | `8080` | Порт автозапуска (должен совпадать с `base_url`). |
| `autostart` | `true` | Запускать хаб, если он не работает. |
| `state_file` | `~/.care/agent-hub.json` | Где хаб хранит развёртывания. |
| `agent_server_cmd` | `["carl-agent-hub", "serve"]` | Команда автозапуска (к ней добавляются `--port` / `--state-file`). |
| `start_timeout` | `15` | Сколько секунд ждать `/healthz` после автозапуска. |
| `timeout` | `30` | Таймаут одного запроса к управляющему API. |

См. [Конфигурация → разделы](/ru/care/configuration/sections/).

## Из CLI

У `/deploy` есть аналоги без интерфейса: `maestro deploy`,
`maestro deployments` и `maestro metrics`. Одна оговорка: CLI **не**
запускает хаб сам, он должен уже работать. См.
[Развёртывание в хаб агентов](/ru/care/cli/deploy/).

## Замечания

- В приложении нет кнопки развёртывания. Агент в чате может выполнить
  `maestro deploy` через мост команд CLI, и этот вызов спросит
  подтверждение. Мост выключен, если память цепочек — IdeaL.
- Нужна **Memory** (реестр цепочек), как и для других команд Production.
- Чтобы просто отправить цепочку POST-запросом во внешний сервис, а не в хаб,
  см. [`/upload`](/ru/care/slash-commands/production/).
