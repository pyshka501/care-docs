Эволюции нужен набор данных: примеры задач с ожидаемыми ответами, по которым
оценивается каждая цепочка-кандидат. **Генератор данных для эволюции**
Maestro (фабрика бенчмарков) создаёт такие примеры для цепочки, проверяет их
программно и хранит как версии набора данных.

## Запуск генерации

Три способа, все в приложении:

- **Библиотека → Наборы данных** → **Сгенерировать данные для эволюции**.
  Нужна открытая сессия.
- Карточка цепочки в Библиотеке → **Данные для эволюции**. Кнопка готовит
  запрос для агента, отправляете его вы.
- Попросите агента в чате, например *«сгенерируй данные для эволюции
  цепочки про сумму чека»*.

Поля формы:

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| Задача | из цепочки | Что должна делать цепочка. |
| Тип заданий | Ответ текстом | **Ответ текстом**: агент получает вход и отвечает, ответ сравнивается с эталоном. **Задачи с инструментами**: агент действует через инструменты в чистой среде, проверяется итоговое состояние и ответ. |
| Примеров | 24 | Сколько примеров получить. |
| Сложность | сбалансированно | проще, сбалансированно или сложнее. |
| Закрытая часть, % | 25 | Доля скрытых примеров (0–50). |
| Бюджет, токенов | 200 000 | Жёсткий предел для этой генерации. |
| Требования (необязательно) | — | Например, «больше случаев с неоднозначными формулировками». |

**Запустить генерацию** начинает процесс. Нажатие кнопки — ваше согласие,
дополнительного окна нет. Если генерацию запускает агент из чата,
приложение вместо этого покажет одно окно подтверждения. Генерация
использует **модель чата** сессии и останавливается, не превышая бюджет.

## Пока идёт генерация

Карточка процесса показывает стадии и примеры по мере проверки. Можно:

- **Пауза** и **Продолжить**;
- **Повторить неудачные** части;
- **Остановить и сохранить**: процесс завершается окончательно, проверенные
  примеры сохраняются;
- отправить **инструкцию**, например *«добавь больше случаев с
  неоднозначными именами»*. Изменения по инструкциям показываются отдельно.

Эти действия бесплатные: бюджет подтверждён при старте.

Примеры разбиты на группы: принятые, отклонённые, устаревшие и без
проверки. Примеры закрытой части показываются без эталонных ответов.

## Версии набора

Завершённый процесс сохраняет версию набора с id вида `bf_<16 hex>.v<N>`. У
каждой версии указаны примеры поисковой части, закрытой части, отклонённые
примеры, версия спецификации и оценщик.

**Использовать для эволюции** кладёт в поле ввода запрос на эволюцию цепочки
на этой версии. В эволюцию передаётся только **поисковая часть**. Закрытая
часть остаётся в локальном хранилище и никогда не возвращается в разговор.

Версию можно использовать для эволюции, только если:

- в ней минимум два проверенных примера поисковой части;
- её оценщик поддерживается (сравнение текста на равенство или по шаблону);
- это не набор *задач с инструментами*.

На набор можно ссылаться и словами («последний набор для цепочки про чек»),
агент превратит это в `dataset:<id>`.

## Хранение

Процессы и наборы хранятся в локальном файле SQLite:

```bash
# по умолчанию
~/.local/state/care/benchmark-factory/factory.sqlite3
# переопределение
export CARE_BENCHMARK_FACTORY_DB=/path/to/factory.sqlite3
```

Учётные данные модели процесса хранятся только в памяти. Процесс, прерванный
перезапуском приложения, нужно явно продолжить из той же сессии.

## Ограничения

- Наборы **задач с инструментами** можно сгенерировать, просмотреть и
  экспортировать, но пока нельзя использовать для эволюции: оценщик эволюции
  сравнивает только текст ответа.
- Закрытая часть пока не используется для сравнения результатов эволюции.
  Этот этап недоступен.
- Эти наборы отделены от наборов TUI/CLI (`maestro dataset …`, `/dataset …`),
  которые хранятся как карточки памяти.
