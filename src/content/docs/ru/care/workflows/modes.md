В Textual TUI (`maestro tui`) два режима. **Interactive** — режим по
умолчанию. Он заменил прежний режим **Ad-Hoc**: старое имя `ad_hoc` всё ещё
принимается и читается как `interactive`.

В приложении режимов нет. Там агент в чате делает то, о чём вы просите
(генерация, запуск, сохранение, эволюция), а платные шаги спрашивают одно
подтверждение. См. [Приложение](/ru/care/app/overview/).

| | **Interactive** (по умолчанию) | **Production** |
| --- | --- | --- |
| На каждый запрос | Сгенерировать цепочку, **спросить перед запуском**, показать ответ. | Сгенерировать воспроизводимую цепочку, спросить один раз, затем сохранить, выполнить базовый прогон и запустить эволюцию. |
| Следующий запрос | Новая генерация. Агент может зацикливаться на своём ответе (до `CARE_CHAT__LOOP_MAX_ITER`, по умолчанию 5). | Правит сохранённую цепочку в новую версию. `/new` начинает новую цепочку. |
| Сохранение и эволюция | Кнопки **Save** и **Evolve**; автоматически ничего не сохраняется. | Автоматически. |
| Нужна Memory | Нет. | **Да.** Без Memory TUI с предупреждением возвращается в Interactive. |
| Нужна платформа | Только для Evolve. | По желанию. Без неё сохранение и базовый прогон выполняются, эволюция пропускается. |

Переключение: переключатель над полем ввода или `/mode`. Режим при старте
задаёт `CARE_CHAT__DEFAULT_MODE`.

## Interactive

Введите задачу: генератор строит цепочку, TUI спрашивает перед запуском и
показывает ответ. Ничего не сохраняется, пока вы не нажмёте **Save**
(сохранить в библиотеку) или **Evolve** (открывает выбор запуска эволюции).
Режим подходит, чтобы пробовать задачи и дорабатывать цепочку, прежде чем
оставить её.

## Production

Каждый запрос даёт одну воспроизводимую цепочку. Она сохраняется в Memory
под постоянным `chain_id`, один раз выполняется как **базовый прогон**
(записывается первой записью набора данных) и передаётся в эволюцию, если
платформа настроена. Следующий обычный запрос правит эту цепочку. Подробнее:
[Режим Production](/ru/care/workflows/production/).

## Политика этапов

Оба режима проходят один конвейер: генерация → запуск → сохранение →
базовый прогон → эволюция. Генерация всегда автоматическая. У остальных
четырёх этапов есть политика:

| Политика | Поведение |
| --- | --- |
| `auto` | Выполнить без вопроса. |
| `ask` | Сначала спросить подтверждение. |
| `skip` | Никогда не выполнять (зависимые этапы тоже пропускаются). |

По умолчанию:

| Этап | Interactive | Production |
| --- | --- | --- |
| `run` | `ask` | `ask` |
| `save` | `skip` (кнопка Save) | `auto` |
| `baseline` | `skip` | `auto` |
| `evolve` | `skip` (кнопка Evolve) | `auto` |

## Переопределение через окружение

```bash
# Режим при старте: interactive | production
export CARE_CHAT__DEFAULT_MODE=production

# Политика этапа: CARE_CHAT__MODE__<MODE>__<STAGE> = ask | auto | skip
export CARE_CHAT__MODE__INTERACTIVE__RUN=auto    # запуск без вопроса в Interactive
export CARE_CHAT__MODE__PRODUCTION__SAVE=ask     # спросить перед сохранением в Production
```

`<MODE>` — `INTERACTIVE` или `PRODUCTION`; `<STAGE>` — `RUN`, `SAVE`,
`BASELINE` или `EVOLVE`. Незаданный этап берёт значение по умолчанию из
таблицы выше.

:::note[Мягкий разбор]
`default_mode` никогда не ломает загрузку конфигурации. `ad_hoc`, `ad-hoc` и
`adhoc` читаются как `interactive`, `prod` как `production`. Всё остальное
отбрасывается с предупреждением в логе, и действует значение по умолчанию
(`interactive`).
:::

Настройки `CARE_CHAT__AD_HOC_HISTORY_TURNS` (по умолчанию 6) и
`CARE_CHAT__AD_HOC_HISTORY_CHARS` (по умолчанию 1200) сохранили старое
написание. Они задают, сколько прошлого разговора видит следующий запрос в
Interactive.
