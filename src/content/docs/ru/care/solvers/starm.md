Часть подзадач в цепочке алгоритмическая: заполнить судоку, найти путь в
лабиринте, восстановить операторы в арифметической головоломке. LLM-шаг с этим
справляется ненадёжно. Maestro может отдать такие задачи небольшим рекурсивным
моделям (HRM, TRM и другим, обученным в [STARM](https://github.com/ai-forever/STARM))
на GPU-сервере и проверить ответ локально, прежде чем его увидит следующий шаг.

Интеграция перенесена из AIRI-MAESTRO/care#1, автор — Юлиана Шахвалиева.

## Инструменты

Каждое семейство задач — отдельный встроенный инструмент, генератор цепочек выбирает
его по имени. Инструмент существует, только если для задачи настроен порт сервера.

| Инструмент | Ключ `starm_ports` | Вход | Локальная проверка ответа |
| --- | --- | --- | --- |
| `solve_sudoku(input_grid)` | `sudoku` | 81 клетка; `.` или `0` — пусто | Да: полная сетка, все исходные цифры на месте, нет повторов в строках, столбцах и блоках |
| `solve_maze(input_maze)` | `maze` | Квадратная сетка: `#` стена, пробел проход, один `S`, один `G` | Да: путь от `S` до `G` по проходам, не длиннее кратчайшего |
| `solve_arithmetic(input_expression)` | `arithmetic` | Постфиксная запись (RPN), `?` на месте каждого неизвестного оператора, затем `=target` | Да: подставленные операторы дают целевое значение |
| `solve_game_of_life(input_pattern, evolutions)` | `game_of_life` | Узор в `o` / `b` / `$` (без счётчиков повторов) или строки `.` / `O` | Да: симуляция B3/S23 с точностью до сдвига (до 10 000 шагов) |
| `solve_arc_agi_1(input_grid, puzzle_id, few_shot)` | `arc_agi_1` | Строки сетки и id задачи или её демонстрационные пары | Только формат |
| `solve_arc_agi_2(input_grid, puzzle_id, few_shot)` | `arc_agi_2` | То же | Только формат |

Арифметика записывается **постфиксно**. Инфиксный запрос вроде `3?5=15` отклоняется
ещё до отправки.

## Подключение сервера STARM

Один процесс STARM обслуживает один чекпойнт, то есть одну задачу. Поэтому у каждой
задачи свой порт. Серверу нужна GPU с CUDA и установленный `flash-attn`.

```bash
# в checkout STARM, на GPU-хосте
pip install -r api/requirements.txt
./host_model --path_directory checkpoints/sudoku/<run>     --device cuda:0 --port 8080 &
./host_model --path_directory checkpoints/arithmetic/<run> --device cuda:1 --port 8081 &
```

Подходят и публичные чекпойнты HRM с Hugging Face Hub, например
`--path_directory sapientinc/HRM-checkpoint-sudoku-extreme --seq-len 81`.

Maestro использует два endpoint каждого сервера:

- `GET /info` — какую задачу обслуживает чекпойнт, архитектура, предел шагов
  рекурсии и, для лабиринтов, длина последовательности (размер сетки).
- `POST /generate` — один запрос, один ответ.

### Настройка

В `~/.config/care/config.toml` (или `./care.toml`):

```toml
[tools]
starm_host = "http://gpu-01"   # без порта: каждая задача добавляет свой
starm_timeout = 120            # секунд на вызов (по умолчанию 120)

[tools.starm_ports]
sudoku = 8080
arithmetic = 8081
```

Или через переменные окружения:

```bash
CARE_TOOLS__STARM_HOST=http://gpu-01
CARE_TOOLS__STARM_PORTS=sudoku=8080,arithmetic=8081    # можно и JSON-объект
CARE_TOOLS__STARM_TIMEOUT=120
```

- `starm_host` по умолчанию `http://localhost`.
- Допустимые ключи: `sudoku`, `maze`, `arithmetic`, `game_of_life`, `arc_agi_1`,
  `arc_agi_2`. ARC-AGI-1 и ARC-AGI-2 — разные чекпойнты на разных портах.
- Неизвестный ключ или негодный порт отбрасывается с предупреждением. Maestro
  всё равно запускается, просто у задачи не будет инструмента.
- Если `starm_ports` пуст, решателей нет и ничего не меняется.
- Решатели — встроенные инструменты: `tools.enable_builtins = false` выключает их
  вместе с остальными.

### Проверка

```bash
maestro doctor
```

`doctor` вызывает `GET /info` у каждого настроенного сервера и для каждого
инструмента печатает `ok`, `misrouted` (сервер обслуживает другую задачу, обычно
перепутаны порты) или `unreachable`. См.
[Команды настройки](/ru/care/cli/setup/#maestro-doctor).

## Что происходит при вызове

1. **Аргументы разбираются локально.** Неверный запрос падает здесь, до отправки:
   инфиксная арифметика, лабиринт без `S`, судоку не из 81 клетки, непрямоугольная
   сетка ARC.
2. **Отправляется один `POST /generate`** на сервер задачи.
3. **Ответ проверяется**, если задача это позволяет (см. таблицу выше).
4. **Возвращается** ответ, затем `Checked: …` или `Not checked: …` и число шагов
   рекурсии, которое сделала модель.

### Ошибки

Как выглядит ошибка, зависит от того, где работает цепочка.

**В приложении** (нативное исполнение цепочек в строгом режиме) ошибки
типизированы. Шаг цепочки не может завершиться успешно без ответа или с
опровергнутым ответом:

| Ошибка | Когда |
| --- | --- |
| `MAESTRO_STARM_INVALID_INPUT` | Аргументы не превращаются в запрос, или сервер отклонил формат. |
| `MAESTRO_STARM_UNAVAILABLE` | Нет сервера, ошибка HTTP или сервер другой задачи. |
| `MAESTRO_STARM_ANSWER_REJECTED` | Сервер ответил, а локальная проверка доказала, что ответ неверен. |

**В CLI и Python-библиотеке** те же ошибки возвращаются читаемым текстом для
следующего LLM-шага. Опровергнутый ответ приходит с пометкой
`REJECTED by a local check: <reason>. Do not use this answer as correct.`

## Ограничения

- **ARC решается только для задач, на которых обучен чекпойнт.** Чекпойнт хранит
  каждую задачу в обученном эмбеддинге, который выбирается по `puzzle_id`. У новой
  задачи эмбеддинга нет. Если id неизвестен, но есть демонстрации, их можно
  передать в `few_shot`: Maestro найдёт id во встроенных индексах (960 задач
  ARC-AGI-1 вместе с ConceptARC, 1 120 задач ARC-AGI-2). Для поиска нужен полный
  набор демонстраций задачи. Ответы ARC проверить нельзя, считайте их
  предложениями.
- **Чекпойнт лабиринтов знает один размер сетки** (30×30 у опубликованного).
  `solve_maze` берёт размер из `GET /info`, обносит меньший лабиринт стенами до
  этого размера и обрезает ответ обратно. Лабиринт больше отклоняется. Маленькие
  лабиринты всё равно вне распределения: на чекпойнте 30×30 из 40 случайных
  лабиринтов от 5×5 до 20×20 без обноски решено 0, с обноской 20.
- **Остальные задачи принимают только форматы обучения:** судоку 9×9,
  однозначная постфиксная арифметика, небольшие узоры «Жизни».
- **Развёрнутые агенты этих инструментов не содержат.** Проверка перед деплоем
  отмечает цепочки, которым они нужны.

## Измеренные результаты

Замер от 2026-10-05: публичные чекпойнты HRM на сервере STARM
(ai-forever/STARM@38c65c6), одна GPU H200 с flash-attn 2.8.3, вызовы через эти
инструменты, выборки из тестовых наборов HRM с фиксированным seed.

| Набор | Выборка | Модель права | Неверных ответов поймано проверкой | Верных ответов отклонено |
| --- | --- | --- | --- | --- |
| sudoku-extreme | 1 000 | 51,9% | 481 / 481 | 0 |
| maze-30x30-hard | 200 | 77,5% | 45 / 45 | 0 |

По лабиринтам 68,5% ответов совпали с путём из датасета, ещё 9% — другой
кратчайший путь. Медианная задержка вызова 0,14 с (судоку) и 0,07 с (лабиринт).

Локальная проверка поймала все неверные ответы в обеих выборках и не отклонила ни
одного верного. Сама модель на сложных судоку часто ошибается. Именно проверка не
пускает такие ответы дальше по цепочке.

Сквозной прогон: генератор цепочек (OpenRouter, режим fast) по запросам на русском
про судоку и лабиринт собрал цепочки, которые вызвали `solve_sudoku` /
`solve_maze` с правильно оформленным входом. Эти цепочки прошли 3/3 шага в строгом
режиме приложения против серверов на H200. Генерация была одна на задачу: это
показывает, что путь работает, но не то, как часто генератор справляется.

**Не проверено:** чекпойнты арифметики, «Жизни» и ARC через эти инструменты не
запускались. Их разбор и проверки покрыты только юнит-тестами.
