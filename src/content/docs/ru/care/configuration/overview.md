## В приложении

Важны два источника:

1. **Настройки → Модель чата** (настройки харнесса): провайдер, ключ и
   модели. В приложении эта модель выполняет всю работу Maestro с моделью:
   генерацию, запуск, исправление, генерацию данных, черновики мастерской,
   перевод идей.
2. **Настройки → MAESTRO**: память, IdeaL, веб-исследование, платформа
   эволюции, блокировка приложения. Страница пишет поля `CareConfig` (см.
   ниже) и ссылки на Keychain. После каждого сохранения нужен полный
   перезапуск. См. [Настройки](/ru/care/app/settings/).

Провайдер, URL, модель и ключ из `CARE_MAGE__*` приложение для генерации
**не** использует. Они настраивают CLI, TUI и старый workbench.
`CARE_MAGE__MODE` и переключатели исследования в приложении действуют.

## Четыре уровня

`CareConfig` (в `care/config.py`) читается из четырёх уровней, по
возрастанию приоритета:

1. значения по умолчанию в `care.config.CareConfig`;
2. `~/.config/care/config.toml` (глобально для пользователя);
3. `./care.toml` в рабочем каталоге (для проекта);
4. переменные окружения `CARE_*` (высший приоритет). При старте CLI также
   загружает `./.env`; переменные, уже заданные в оболочке, важнее.

[`maestro init`](/ru/care/cli/setup/) пишет стартовый `.env` для CLI и TUI.
[`maestro doctor`](/ru/care/cli/setup/) показывает заданные переменные, путь к
конфигурации, установленные extras и живые проверки Memory, MAGE и
платформы.

## Соответствие TOML и окружения

Вложенные поля в форме переменных окружения разделяются двойным
подчёркиванием:

```toml
[memory]
base_url = "http://localhost:8002"
retrieval_backend = "ideal"
ideal_namespace = "my-team"
```

то же самое, что:

```bash
CARE_MEMORY__BASE_URL=http://localhost:8002
CARE_MEMORY__RETRIEVAL_BACKEND=ideal
CARE_MEMORY__IDEAL_NAMESPACE=my-team
```

## Разделы

У `CareConfig` двенадцать разделов:

| Раздел | Префикс окружения | Назначение |
| --- | --- | --- |
| `mage` | `CARE_MAGE__*` | Генератор цепочек: режим, исследование, лимиты, топология. Провайдер/URL/модель/ключ для CLI, TUI, старого workbench. |
| `memory` | `CARE_MEMORY__*` | URL и ключ GigaEvo Memory, режим только для чтения, бэкенд памяти цепочек, пространство IdeaL. |
| `platform` | `CARE_PLATFORM__*` | URL и ключ платформы эволюции, модели мутации и валидации. |
| `hub` | `CARE_HUB__*` | Хаб агентов для `/deploy` и `maestro deploy`. |
| `upload` | `CARE_UPLOAD__*` | Внешний адрес для отправки цепочек (`/upload`). |
| `sandbox` | `CARE_SANDBOX__*` | Песочница навыков: бэкенд (`docker` по умолчанию, `e2b`, `firejail`, `local`), лимиты, сетевая политика. |
| `tools` | `CARE_TOOLS__*` | Каталог `@carl_tool`, встроенные инструменты, веб-поиск, выполнение кода, синтез инструментов, решатели STARM. |
| `telemetry` | `CARE_TELEMETRY__*` | Необязательный приёмник событий (Langfuse). |
| `defaults` | `CARE_DEFAULTS__*` | Язык ответов, язык TUI, отображение DAG, размер истории, уменьшение анимаций. |
| `chat` | `CARE_CHAT__*` | Режимы TUI и политики этапов. |
| `context` | `CARE_CONTEXT__*` | Постоянный контекст `CARE.md` и долговременная память. |
| `artifacts` | `CARE_ARTIFACTS__*` | Куда копируются файлы, созданные цепочками. |

Ключи по разделам: [Справочник разделов](/ru/care/configuration/sections/).
Аннотированный список переменных — `.env.example` в репозитории Maestro.

## Переменные вне `CareConfig`

| Переменная | Смысл |
| --- | --- |
| `CARE_BENCHMARK_FACTORY_DB` | Файл SQLite генератора данных для эволюции. По умолчанию `~/.local/state/care/benchmark-factory/factory.sqlite3`. |
| `MAESTRO_APP_LOCK_MODE` | Задать блокировку приложения на один запуск: `disabled` или `touch-id`. |
| `CARE_LOG_FILE`, `CARE_LOG_LEVEL` | Писать лог в файл; уровень (по умолчанию `INFO`). |
| `CARE_CHAT__LOOP_MAX_ITER` | Предел цикла Interactive в TUI (по умолчанию 5). |
| `CARE_CHAT__GENERATION_MAX_ATTEMPTS` | Повторы генерации в TUI (по умолчанию 3). |
| `CARE_CHAT__AD_HOC_HISTORY_TURNS`, `CARE_CHAT__AD_HOC_HISTORY_CHARS` | Контекст следующего запроса в TUI: число реплик (по умолчанию 6) и символов на реплику (по умолчанию 1200). |

Переменные для разработчиков выбирают runtime харнесса и его каталог данных,
см. `maestro app --help`. Приложение задаёт для процесса инструментов ещё
внутренние переменные `MAESTRO_HARNESS_*`. Не задавайте их вручную.

## Секреты

- В приложении ключи вводятся в нативных диалогах и хранятся в Keychain
  macOS. В файлах конфигурации только ссылки `keystore://`.
- `maestro init` пишет ключ генератора в `.env` **открытым текстом**.
- `maestro migrate-secrets` переносит явные значения `*_api_key` из
  `~/.config/care/config.toml` в хранилище ОС и переписывает файл со
  ссылками `keystore://`.
